# Spine 动画制作

通过 `spine-mcp-server` 完成工程读取、动画编辑、回读验证和预览。优先复用现有角色的绑定、动作与附件组合；按用户需求决定动作和风格。

## 按需读取

- 制作流程、工具参数及操作陷阱：[references/mcp-workflows.md](references/mcp-workflows.md)。第一次编辑、新建骨架、处理网格或导出时读取相应段落。
- 延续参考女主的动作或美术组织：[references/main-girl.md](references/main-girl.md)。包含实测骨骼映射、19 段动画、附件变体和已知问题；这些名称只适用于参考工程。
- 批量检查导出 JSON：运行 `scripts/inspect_spine_json.py`。它只依赖 Python 标准库，只读导出 JSON，不直接解析或修改二进制 `.spine`。

## 开工与定位

1. 确定实际编辑目标、动作含义、时长、循环与否、是否需要运行时资源。可从现有动作和用户上下文推断的信息直接采用，并说明重要假设。引用参考工程不等于要求修改它。
2. 发现当前会话的 `spine-mcp` 工具。工具通常显示为 `mcp__spine_mcp__spine_*`；以下使用短名。缺少连接时检查现有 MCP 配置及服务错误，报告具体缺项；不要把编写 JSON 当作已经保存 `.spine`。
3. 先调用 `spine_get_capabilities({projectPath})`，再调用 `spine_check_project`；需要层级与控制对象时读取 `spine_describe` / `spine_get_project_info`。按需读取 `spine_get_animation_detail`、`spine_get_attachments`、`spine_get_mesh`。当前实测支持 3.8；其他系列以能力查询结果为准，不通过改版本字符串绕过限制。
4. 一次导出 JSON 到工作目录，后续分析和预览复用这份快照；写入后重新导出。检查 `skeleton.images`、实际 `images/`、atlas 内页面名称及图片路径。导出 JSON 所在目录改变时，相对图片路径不会自动指向原资源。
5. 用骨骼父子关系、插槽绑定、网格影响和线框预览确认控制对象。自动角色匹配只是线索；参考工程只有 `root` 自动匹配，不能直接套用整骨架模板。

## 选择编辑方式

| 需求 | 优先方案 |
| --- | --- |
| 调整已有角色动作、生成风格一致的新动作 | 完整复制最接近的动画，再局部修改 |
| 精确设计主姿势与节奏 | 编辑完整动画对象，或 `spine_pose_to_animation` 后补附件、FFD 等轨道 |
| 标准骨架快速草稿 | `spine_generate_animation`，先核对骨骼名到角色的 `roleMap` |
| 单轨关键帧修改 | `spine_edit_keyframes`，时间轴用分段数组 |
| 多骨骼、插槽和形变一起修改 | `spine_edit_animation` / `spine_batch_edit`，合并为少量事务 |
| 只有已拆分 PNG | 装配、检查枢轴与层级，再制作动画，见工作流文档 |

修改 `.spine` 的 MCP 调用按工程串行执行。工具会后台导出和重建，逐骨骼逐帧反复调用成本高。同一工程不要同时由编辑器保存和 MCP 写入；写入冲突时重新读取后再应用修改。

## 动作设计与实现

- **先主运动，再附属运动。** 确定重心、支撑脚、躯干和手臂的关键姿势，再补头部、发梢、衣摆、表情与效果。头发和衣摆依动作产生适量滞后与回弹，幅度按角色比例和实际预览调整。
- **保留完整轨道。** 复制动作时同时保留 `bones`、`slots`、`deform`、约束、事件及 `drawOrder`。原动画没有的轨道不必补空结构。参考角色的眨眼使用面部 FFD，走跑还依赖手部换图与绘制顺序。
- **IK 与 FK 按原绑定工作。** 已受 IK 驱动的腿，优先调整脚部目标和身体控制器；需要 FK 时明确安排 IK mix，避免只转大腿而被约束覆盖。不要把 IK 目标再映射为大腿模板角色。
- **区分 setup 与动画值。** `spine_set_bone` / `spine_set_slot` 改默认姿态；动作修改写动画轨道。动画旋转、位移是相对 setup 的偏移，缩放为倍率。JSON 字段为 `rotate[].angle`，单骨骼工具参数为 `rotation`。
- **统一时间单位。** 批量工具的 `time` 是秒，`frameIndex` 是帧号。先确认工程 FPS；导出数据的时间网格只能辅助推断。生成/预览工具的 `fps` 可能只是采样密度，不能据此改变工程帧率。
- **插值服务于动作。** 主动作可用贝塞尔缓入缓出，匀速段用线性；换图、隐藏和刻意停顿按离散节奏处理。原有阶跃与贝塞尔不一律覆盖。`merge` 会替换所提供的整条时间轴数组；局部补帧优先 `upsert`。
- **循环包含全部视觉状态。** 检查首尾姿势、速度趋势、IK、FFD、附件可见性和绘制顺序。末帧与首帧相等仍需看接缝；单次动作按需要保持结束姿势或回到指定待机。
- **先保留网格拓扑和权重。** 修改 FFD 前用 `spine_get_mesh` 读取逻辑顶点，确定固定点。已有 FFD 时不为消除报错直接使用 `deformPolicy="clear"`，它会删除该附件在全部动画中的形变。拓扑、权重确需改变时先在工作副本处理，并重建受影响形变。

## 保存、验证与交付

1. 优先用独立动画名和 `mode="create"` 保存新动作；明确需要覆盖现有动作时再使用 `replace`。支持 `dryRun` 的复杂编辑先校验同一组参数，再正式写入；dry-run 成功不代表 CLI 已完成回读。
2. 检查工具的错误、警告和备份路径。JSON 重建保留可导出数据，编辑器文件夹、视图等专有状态依赖原始 `.spine` 备份。
3. 写入后运行 `spine_validate_references`，重新读取动画名、时长和受影响轨道；对照基线检查非目标动画、骨架、皮肤及约束未意外改变。
4. 显式提供 `atlasPath` 与 `imagePath`，用 `spine_render_preview(mode="sequence")` 看整段动作，并检查返回的 `renderer`。线框用来检查绑定；纯画面用来检查穿插、形变和层次。sequence 采样不含精确终点，循环接缝和单次动作结尾另外取样。预览不可用时明确未完成视觉验证。
5. 有渲染接缝时对照源贴图和编辑器/目标运行时，区分预览器问题与工程问题。参考工程的本次 MCP 预览可见脸部三角接缝，不应据此直接修改脸部拓扑。
6. 按需求交付 `.spine`、预览和运行时资源。动画编辑不会自动更新旧 `.skel`；需要运行时交付时重新导出 JSON 或二进制，并核对 atlas、所有页面图片、纹理名及目标运行时版本。没有修改贴图时可以复用已核对的图集。

完成回复给出实际工程/动画名、产物路径、验证结果和仍存在的具体问题；不要把参考工程原有缺陷当作新动作已通过验收的依据。
