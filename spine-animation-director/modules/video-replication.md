# 视频直接复刻

用于用户给出视频要求制作 Spine，或同时给出视频与图片 / PSD 的任务。默认还原原片，用户明确要求改编时再转动作设计。统一闭环为：**原片分析 → 当前素材的完整预览 → 用户验收 → 冻结 → Spine 实现 → 保存后逐帧核对**。

## 建立同一时间与画面基准

- 实际播放原片，再查看逐帧和局部。记录文件 / 哈希、采用片段的起止时间、源尺寸、实际时间戳 / FPS、朝向、镜头及主体位移。用户未指定片段时根据明确动作选定并说明；多个不相容片段无法判断时才询问。
- 预览时间从零开始，保留 `源视频时间 ↔ 预览时间 ↔ 帧索引` 映射。说明帧号从 0 还是 1 开始，用户指出“第 N 帧”时核对 FPS 和片段偏移，不能把它当作第 N 秒或随意跳到邻近姿势。变帧率视频按真实时间戳采样，不只用总帧数除时长。
- 区分角色 root、镜头移动和背景；全片使用一致的固定对齐，不逐帧自动居中 / 缩放来遮掉位移或形变。选择原地循环或保留位移须与原片及用户用途一致，不擅自去除运动。
- 分别记录主体周期与局部一次性动作。例如步态每秒重复，不代表抖耳、眨眼或甩鬃也每秒重复。循环截取以原片实际可闭合片段为依据，不能平滑掉停顿、抬脚、快速折回等可见特征。

## 逐部件观察，再制作预览

用当前主体列一份短动作清单：`部件 / 侧别 + 开始、极值、恢复时间 + 轮廓变化 + 接触 / 遮挡 + 可见依据`。同类近远件逐一观察，不用“耳朵已动”“四腿已检查”代替每一件的结果。重点包含主体、四肢末端、双侧小件、毛发 / 衣料、手物接触及载具 / 道具的实际活动部位。

图片 / PSD 用于保持身份、线稿、颜色和部件；视频用于保持姿势、路径、幅度、相位、停留、局部形变及层次。只给视频时，从清晰帧准备独立部件并补齐必要遮挡区。不可见阶段按邻帧与结构推定并记录，低清晰度不能成为虚构精确匹配的依据。跟踪点与光流仅用于测量，归属与轮廓以实际画面复核。

先用真实部件和必要补图制作完整效果帧，方法沿用 [最终效果预览](interactive-preview.md)。原片直接播放只说明参考是什么，不能冒充“当前素材已复刻”的预览；只有用户明确认可原视频帧本身为最终视觉目标，且其外观与素材可实现时，才可直接冻结这些帧。整车 / 整角色帧图可用于预览，正式 Spine 仍须由实际独立部件实现。

原片与待验收预览共用时间轴并排播放，提供准确时间 / 帧号、暂停、逐帧、慢放及有用的局部放大。先正常速度看整段，再按局部事件的开始、峰值、回收及相邻帧检查；被用户指出的脚、外侧小件或毛发等登记为明确检查点。自查明显缺陷后才交用户验收，不把骨架代理、运动轨迹或原片播放器当成已完成预览。

## 验收后只还原，不重新估计

用户确认具体版本后，按 [冻结与交接](interactive-preview.md#冻结与交接) 保存全部帧、素材、时间和生成依据。参考视频、冻结目标、实际 Spine 三者保留独立身份。未确认时继续修预览；用户确认后或明确说按该版开始制作时，直接进入 Spine，不重复询问同一范围。

优先复用预览的变换、曲线、部件形变映射、换图与绘制顺序，转换为骨骼、网格、权重或 FFD。简单骨骼曲线能保持画面时不堆高密度网格；需要烘焙时保留独立部件，并检查关键帧之间的插值。不要重新跟踪一套“差不多”的轨迹，也不以整角色逐帧换图代替可编辑绑定。

最终依据是 [保存后实际 Spine 与冻结预览的同帧对照](../../spine-skill/modules/delivery.md#与已验收预览同帧对照)。视频用于追溯运动，已确认预览用于判定本次实现是否完成；不能把“原片像素不同”当作忽略 Spine 偏离已确认目标的理由。若目标本身要改变，先提交新版完整预览确认，不能反向覆盖旧目标。
