# 参考选择与动作校准

用于新动作设计、整体重做和“幅度太小/没表现”的修正。先用真实通过的动作建立判断依据，再设计当前角色；不将用户否定的试作或虚构示例当质量基线。

## 选择和读取

1. 从 [已验收动作索引](../references/accepted-motion-library.md) 找用途、情绪、持物/支撑关系相近的片段。体型、朝向和画风影响适配方式，不能因为都有武器就复制同一整套动作。可用一个参考负责状态节奏、另一个负责接触关系，无需机械凑足数量。
2. 确认实际参考根目录，按索引的相对路径定位；不在安装技能内假设缓存存在。核对源哈希或版本后复用快照，变更时重新只读导出。查询能力、读取工程和预览参数沿用 Spine 技能，真实图集可能位于工程的 `out/`，体检未自动找到不等于没有图集。
3. 查看 setup、动画开始、主要极值、换图/接触前后和正常速度循环。动画起始姿势可能由 t=0 换图和骨骼偏移另建，setup 不是强制动画起点。不得仅凭名字、关键帧数量或静态四等分图认定行为。
4. 在 brief 记录一张参考卡：`工程相对路径 + 源版本/哈希 + 动画名/时长 + 实际所看预览/时间 + 角色状态/主姿势 + 主动与跟随部位 + 接触关系 + 采用项/差异`。只读取结构而未播放时明确此限制，不能声称已学到节奏。

## idle 的三种任务

| 类型 | 已验收依据 | 设计与交付语义 |
| --- | --- | --- |
| 常驻基础循环 | 女主 `idle`；衙役 `idle_normal` | 稳定、可连续重复，主姿势本身表达身份；有目的的局部变化与呼吸可以成立，但不靠整张图升降代替主体运动 |
| 情绪状态循环 | 书生、混混的 `idle_normal / idle_urgent / idle_angry` | 先设计持扇、扶头、指责或持棍等状态姿势，再做相应循环；不是每一轮从普通姿势演到焦急再返回 |
| 偶发待机小动作 | 女主 `idle_act_1 / idle_act_2 / idle_act_3` | 保留起承收势与回到基础 idle 的语义；抬手、摸头等不一定要每个基础周期重复。是否拆为独立动画、由谁触发按项目/用户需求约定，不凭名称编造已有调度逻辑 |

用户只要求一个 idle 时，选最接近当前用途和角色状态的一种并说明；不要自动制作整套情绪或另加随机触发程序。需要表现性动作时也不能把它删成胸肩起伏。用户未指定时长时，先参照同类片段实际周期与节拍，避免默认拉成 5–7 秒以容纳空泛文案；样本时长不作为统一上限。

## 从参考到当前角色

先确定**姿势**，再确定**姿势中的运动**。在 brief 中用一句话交代“角色以什么姿态等待/行动，视线在哪里，哪条腿承重，手与道具是什么关系”；随后指出观众能看见的主变化、开始/顶点/回落差异、返回路径与停留。原立绘比例、身份和服装应保持，但不要求所有手脚关系永远冻结。

参考的状态手势可以启发新角色，不能直接移植：农夫抚须说明普通 idle 可以有职业/性格行为，不意味着没有胡须的侠客也要抚须；衙役持刀说明握点与支撑要先成立，不意味着所有持剑者都只做衙役的克制循环。补绘或动作专用附件是实现姿势的手段，不能因单图没有现成像素而先把动作缩小。

## 幅度、节奏和画面比较

- 新作与参考按同一角色显示高度、固定镜头、正常速度查看；同一角色不同状态保持同一缩放/取景。比较总位移时用角色有效高度归一化，排除图集空白、文字、特效和不同拍摄缩放。镜头要容纳全部极限姿势，不能因裁掉剑尖/手臂误判幅度。
- 先并排看起始与峰值剪影、头/胸/骨盆关系、肘与手的位置、道具方向和表情；再连续看发起、保持、回落的节拍。局部骨骼角度受父级与 setup 影响，不能复制“头转 8°”当作视觉同幅度；需要量化时记录世界空间点/可见附件轮廓和测量定义。
- 已验收样本也有幅度差异：混混的头脸摆动明显，衙役普通持刀更稳，女主基础 idle 与 `idle_act_*` 分工不同。数值只定位差距，不设通用像素、百分比、骨骼数或周期作为及格线。
- 用户说过弱时，具体指出是主姿势差异小、重心没有参与、手臂没有独立运动、起落被长时间摊平，还是附属摆动淹没主体；修改对应姿势、路径和间距。保持同尺寸比较修正前后，不能仅把所有曲线统一乘倍数、加风或全段加速。
- 刻意停留、阶跃、快速落点和轻微动作按状态使用；不把“流畅”误写成全程等速或全轨相同缓入缓出。脚、手物接触是否稳定在世界/接触坐标中检查，不能只看局部数值为零。

## 预演能证明什么

优先使用真实参考的交互播放，加当前角色的姿势图和必要的独立关节/道具代理动画。代理图可用轮廓、骨架或简化色块说明屈肘、握持、支撑和轮廓变化，不需要在确认前抢先完成正式切图。

整图位移/扭曲只适合有限的外观或节奏示意，无法证明新手势、手指收握、眼神、真实换重心或刚性物体接触。若这些是方案主要卖点，预演必须用对应的关节/轮廓表达；不能交付看不出该动作的整图摇摆，再靠长段文字和“以后补图”补上缺失主动作。附属细节可以标为未模拟，主要行为不可缺席。正式素材与工程仍遵守现有交互预览确认边界。

## 实现交接

记录参考的可见状态与相关完整通道：骨骼、约束、附件、FFD、draw order。t=0 的附件选择常用于建立另一套状态姿势，不等于每轮中途切换了同样多次图片；从时间轴核实后安排清单。参考技术与素材需求写入 [素材蓝图](asset-blueprint.md)，用目标姿势验证补图与绑定；不复制来源角色纹理或只复制骨骼旋转。
