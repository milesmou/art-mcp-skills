# 最终效果预览

用户于 2026-11-11 明确：先直接生成最终效果预览，验收后 Spine 完全按照这个效果制作。预览可采用 GIF、无损帧动画、交互帧播放器或其他适合观看的方式；默认使用可暂停、逐帧和慢放的无损帧播放器。无需先制作实际 Spine 再导出此预览。

## 最终视觉目标与播放来源

- **内部研究**：参考角色、骨架、色块、关节代理用于研究姿势、接触与节奏，标明内部草案。它们可帮助制作最终效果帧，不能代替用户验收画面。
- **制作前验收版本**：直接用当前角色原画部件、必要补图/替换件合成或绘制完整动作帧，外观与动作达到准备交付的最终观感。允许预览阶段在工作副本制作所需素材，保留实际来源和坐标；此时不制作 Spine 动画。帧中必须包含可见的手/蹄形、关节连接、遮挡、表情、衣发跟随和循环，不能留“正式再补”的主要或局部可见缺项。
- **可复刻性**：预览中的每种姿态、局部轮廓和层次变化应能映射到真实部件、枢轴、骨骼、换图或网格；提前确定刚性件、连续皮肤与活动遮挡的处理。逐帧生成图若身份、比例、纹理或接合漂移，先修正再验收，不能把无法稳定实现的画面交给 Spine 硬拉。
- **Spine 实现结果**：用户确认后，以冻结效果帧为目标，使用对应版本 Spine runtime 查看保存回读后的实际数据，执行 [同帧匹配检查](../../spine-skill/modules/delivery.md#与已验收预览同帧对照)。这份实现检查不能替换或覆盖先前已验收的目标帧。

## 冻结与交接

保留全部无损源帧、源素材/分层、尺寸、FPS、各帧时刻、时长、原点、固定取景、Alpha/背景方式及关键姿势索引；用版本和哈希关联用户确认。GIF 可作观看载体，但它的调色、透明限制和帧时长量化不作为新的美术变化；Spine 依照对应无损帧复刻。预览渲染脚本和部件变换可一并保留，便于复用轨迹与换图时序；不必为简单任务建立额外系统。

目标画面一经通过，不在制作中重生成或覆盖它。技术实现偏差自行修复；需要改变可见效果时出新版目标预览并说明变更，确认后再更新基准。具体实施与偏差判定沿用 [Spine 制作前验收](../../spine-skill/modules/animation.md#制作前交互预览与用户验收) 与 [同帧对照](../../spine-skill/modules/delivery.md#与已验收预览同帧对照)。

## 关节代理的连接与遮挡

自绘关节、枝叶或道具代理可以简化笔触和细节，但应表达方案中真实的连接、枢轴和前后关系。先建立这部分结构，再添加摆动和滞后；它们决定预演能否用于判断正式制作方向。

- **连接点来自实际父级。** 子件的根部从正在绘制的父级轮廓、曲线或关节变换取得；父级弯曲时，绘制与连接使用一致的位置及方向。不要用统一近似坐标另画连接线，或让父子各自位移后靠静态重叠接合。
- **附属运动从连接点传递。** 按“父级 → 连接件 → 末端部件”组织坐标，末端继承连接件的变换，再叠加自身转动或柔性形变。固定根部和接触点保持约束，滞后主要发生在可活动部分。植物可用“主茎 → 侧枝 → 叶片 / 果柄与果实”；其他对象按实际结构选择层级，不强制统一骨链。
- **枢轴与连接件职责明确。** 转轴放在实际接合处，检查连接件到末端是否连续；已有完整连接链时不再补一套独立短柄或装饰线，避免重复线头、断口和错误归属。枢轴重合仍需看轮廓及搭接，不能据此判连接正确。
- **遮挡逐部件决定。** 依据源图及目标姿势安排局部前后关系，不默认“全部叶片后画全部果实”等按类别统一排序。相邻部件的连接归属含混时，先调整根部位置、分支走向或层次，再复看运动；不要仅靠覆盖线头掩盖错误接点，也不要为消除正常遮挡强行拉开原有结构。

局部出现悬空、断口或像从错误部位长出时，先对照源图和准确帧，区分**外观简化、代理连接/层级缺陷、动作姿势或运动路径缺陷**。连接或层级缺陷留在本阶段修正；若修正后目标姿势仍无法成立，再修改动作及素材计划。不能仅因使用了代理就归为“预演原因”，也不能保证正式拆件会自动消除问题。

## 无损帧播放器模板

复用 [交互播放器 HTML](../assets/interactive-preview.html)，复制到任务预览目录，命名 `index.html`。同目录准备 `frames.json` 与 PNG 帧图集。图集每格是完整、相同取景的画面，按行从左到右、再由上到下排列；多个页面按 `sheets` 顺序续排。

```json
{
  "title": "角色 · idle · 最终效果预览 v1",
  "description": "当前角色完整最终效果，供验收后 Spine 复刻。",
  "status": "最终效果待验收",
  "scope": "最终效果无损帧；素材在工作副本完成，尚未制作 Spine 动画。",
  "motion_note": "填写本方案可观察的主要行为。",
  "width": 760,
  "height": 750,
  "fps": 25,
  "duration": 3.2,
  "count": 80,
  "columns": 4,
  "perSheet": 16,
  "sheets": ["frames/sheet-00.png", "frames/sheet-01.png", "frames/sheet-02.png", "frames/sheet-03.png", "frames/sheet-04.png"],
  "beats": [{"time": 0, "label": "P01 起始"}, {"time": 1.2, "label": "P02 接触"}]
}
```

尺寸、帧数、节拍和时长是格式示例，不是动作规格；`beats` 采用真实关键姿势，`blueprint` 可选且为本页相对路径。`scope` 指明内部草案/最终效果目标/Spine 实现及播放方式；只有完整最终效果目标进入制作前验收。动画原始帧率、工程 FPS 与播放器采样帧率分开记录；循环采样通常取 `[0,duration)`，结束状态另验，不为拼接多加一帧停顿。

通过绑定本机回环地址的静态服务打开页面，例如从项目根目录执行 `python -m http.server <端口> --bind 127.0.0.1 --directory <本任务预览目录>`，或复用既有服务。后台启动遵循当前环境约定。不要假设双击 `file://` 能读取 JSON；给用户实际可打开的预览 URL，保留页面与数据以便重开服务。

## 控制与验证

默认提供播放/暂停、上一/下一帧、0.25×/0.5×/1×速度、时间轴、关键姿势定位和缩放；用户选择速度只影响播放，不改源时间轴或正式工程。不同方案对比时用相同显示高度和正常速度。

打开实际页面，检查资源加载、正常速度循环、暂停、逐帧、时间轴、速度选择、关键接触点及缩放；至少核对一次准确帧号/时间跳转。保存观察条件与版本，不以 JS 无报错或首尾数值相同代替画面验收。模板只负责播放，源帧、参考匹配与动作质量由制作流程验证。

连接或遮挡有疑点时，在起始、运动极值及紧邻帧、循环接缝检查同一局部，并回看完整播放。可增加与主画面共用时间和画面来源的局部放大；裁切保持比例，缩放不裁掉受检连接或末端。核对截图中实际显示的帧号与所选时刻一致，页面尚未刷新时重新取图，不能只根据控件值宣称该帧已看过。修复记录沿用 [预览交付前审查](../../spine-skill/modules/delivery.md#预览交付前审查)，不另建一套验收标准。

需要与参考并排时为每个片段准备独立页面，或扩展同一播放器的对照布局；不要把参考 GIF 作为新预览管线的必需输出。播放工具暂不可用时修复入口，或采用用户允许的 GIF/其他帧动画载体，并保留同一套源帧与时间基准。

## 确认与交付

交给用户前，先执行 [预览交付前审查](../../spine-skill/modules/delivery.md#预览交付前审查)，在整段正常播放和局部极值/邻帧中确认动作、接合、局部体积、遮挡与循环。内部代理不能申请最终效果通过；完整效果帧也不能自动证明后续 Spine 已匹配。

用户确认关联到该版目标帧、素材和时间基准。确认后按其复刻 Spine，并提交 [同帧匹配证据](../../spine-skill/modules/delivery.md#与已验收预览同帧对照)；调速、拖动或未回复不等于通过。交付保留冻结目标与最新 Spine 实现的独立入口，明确哪个是目标、哪个是实现结果。只读展示既有参考不增加确认。
