# Spine 自动补图

先读取 [游戏 Spine 切图](game-spine-slice.md)。用于任务已包含补图、防穿帮或动画质量优化时，由代理组织源图检查、局部补绘、导出和复验；不表示 Spine MCP 自带图像生成或像素级碰撞检测。生成式补绘依赖当前可用的图像编辑工具，不能仅靠切图脚本完成。

## 由动作确定补图范围

- 已有动画时接收 Spine 检查结果：工程、动画名、时间或帧号及 FPS、slot/attachment、问题截图和目标姿态。新角色依据要制作的动作列出抬臂、屈肘、屈膝、低头、转头、裙摆展开等实际会出现的姿态，不默认补齐整套 360° 视角。
- 在工作副本隔离部件，区分遮住但已有像素、受蒙版裁掉、完全缺画。肩颈、腋下、肘膝、腰腹、发根和裙片连接处需要真实的颜色、轮廓与搭接；搭接宽度由转轴、转角和形变范围决定，不能用统一像素值或透明 padding 代替。
- 先判断原因：像素缺失才补图；draw order 错误、枢轴偏移、权重塌陷、clipping 或不合适的 FFD 回到 Spine 修正。布料跟随不会自动避开身体，不能靠扩大贴图遮住所有穿插。

## 选择补绘方式

| 现象 | 处理方式 |
| --- | --- |
| 隐藏层、智能对象、蒙版后或其他姿态中有完整部件 | 恢复并对齐现有素材，优先保留原画信息 |
| 小范围缺边、关节搭接、连续色块或纹理 | 在 Photoshop 工作副本用局部复制、修补、绘制与蒙版延展；镜像仅用于结构与光照适用的区域 |
| 较复杂的遮挡区缺画，需要延续线稿、衣褶和材质 | 有可用图像编辑工具时，以原图及局部参考进行生成式补绘，回到 Photoshop 合成与校正 |
| 大幅透视变化、手势或弯曲轮廓无法靠形变成立 | 制作动作专用替换附件；保留与原件共同的稳定锚点，在 Spine 安排换图 |

生成式补绘先查看源图；使用当前工具 schema 支持的参考图输入和局部编辑方式，不凭空编造 Photoshop `batchPlay` 生成命令或不存在的 MCP 补图接口。提示中明确部位、缺口、轮廓走向、画风、线宽、光照和材质，要求保留已完成区域与透明背景。输出有透明背景要求时显式启用工具对应选项；保留参考、提示与实际输出路径以供追溯。

将生成结果视为候选：即使要求保持尺寸，工具也可能改变画布、比例或已有像素。用原图稳定特征配准，将需要的新像素通过局部蒙版合回原件，保留其余原始像素；检查透明 Alpha，不以黑底、白底或棋盘格冒充透明。工具不可用或不能得到可信结果时，继续完成可用源恢复与其他修复，未完成项保持 `needs_redraw` 并说明缺项，不报补绘成功。

## 坐标与现有绑定兼容

- 在源文档坐标系中补绘，再按统一比例测量最终边界。新切图需要扩边时，重新计算 `export_box`、`png_size` 和原位，不把候选图片直接居中替换。生成内容与实际源图层分别记录，不能伪造源层 ID。
- 更新已有 mesh 的贴图时优先保持旧 PNG 的画布、有效像素位置与附件路径，在原画布可用区域内补绘。必须扩画布或改变轮廓时，在副本中同步处理附件变换、UV、网格、权重及关联 FFD；未经验证不覆盖既有纹理。
- 手势、弯曲肢体和转头替换件沿用同一 slot 的锚点、比例与遮挡关系；需要同时显示的补片使用独立 slot，不能误设为互斥附件。仅解决少量关节露缝时不额外生成整套重复角色。

## 补图与动作复验

1. 留下原件、补绘候选及合成后的修复件，候选和对比图放任务的 `previews/`，只有采用的部件 PNG 进入 `images/`；可编辑修复副本另存任务目录，不覆盖源 PSD。
2. 比较 setup 合成与原稿，确认身份、表情、服装细节、线宽和色调未意外变化；透明边缘在浅色、深色背景下检查光晕、杂色和漏底。被遮挡的新像素在动作中暴露时也必须连贯。
3. 对同一极限姿态比较修复前后，检查关节内外侧、轮廓与搭接、换图时的尺寸和锚点；有实际 Spine 动作时回传图片和映射，按 [Spine 预览交付](../../spine-skill/modules/delivery.md) 复验整段动作及衔接。
4. 按 [补图记录](../references/spine/delivery.md#补图记录可选) 记录采用方式、受影响附件和验证证据。仅修复图片但未做动作预览时标为动画待验证；补图完成不等于绑定和动画合格。

若同一处补绘在复验中持续失败，比较候选后保留较好版本，调整拆件、替换附件或动作设计；无改善时停止重复生成，报告尚存问题和已验证的活动范围，不静默缩小用户要求的动作幅度来宣称通过。
