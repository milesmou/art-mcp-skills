# 游戏 UI 切图

使用本工程内置的 [Photoshop UXP 能力](photoshop.md)，通过 `.psjs` 批处理脚本在 Photoshop 内完成整稿等比缩放和素材导出。模板、参考和启动器均随工程提供。

## 执行方式

- 默认读取工程内的 [UXP 执行说明](photoshop.md)，由 [启动器](../scripts/run_uxp.py) 将任务正文与内置 harness 组合并执行；具体切图执行约定见 [UXP 工作流](../references/ui/uxp-workflow.md)。
- 通常分为一次设计稿结构与预览读取、一次资源清单驱动的批量切图；缩放、效果适配、资源隔离、裁切、PNG 无损压缩和清单写出在批处理内完成。集中检查实际导出文件，只对失败或有视觉差异的资源补跑。
- 通过工程内置 UXP 启动器执行；不在每张切图之间发起外部工具调用或重新分析整稿。执行入口不可用时检查 Photoshop 进程、脚本路径和启动器错误，修正可恢复的问题后继续；无法恢复时说明具体阻塞点并保留已完成结果。

## 输入与默认值

- **游戏设计分辨率，必需**：`宽 × 高`，单位为像素，例如 `1080×1920`。缺失时询问，不从 PSD 尺寸或常见机型猜测。
- **设计稿**：用户指定的 PSD、已打开的文档或画板。只有一个明确文档时直接使用；存在多个候选且无法判断目标时询问。
- **切图范围**：优先使用用户指定的图层、图层组、区域或资源清单；未指定时，递归检查全部可见和隐藏图层及图层组，识别独立 UI 资源。默认包含隐藏资源；只有用户明确要求“仅可见图层”等限制时才收窄范围。
- **文字处理**：所有静态文字独立导出，包含标题、按钮文案、提示和标签；由代码显示的动态文字不切图。混合文案按完整语义保留为一张 PNG，仅将动态内容区域设为透明空白，不把两侧静态片段拆成多张图；隐藏动态文字也排除，具体规则见下文。
- **按钮拆分**：默认将每个按钮的静态文字与无文字底图分别导出；多份独立静态文字分别导出，保留效果和原始位置，动态文字只记入清单。
- **进度条拆分**：默认将底图、100% 满进度填充和静态文字分别导出；动态进度数值不导出。填充铺满轨道有效区域，保留圆角、蒙版和效果，导出组件共用画布和中心。用户明确要求原始进度时才保留稿件长度。
- **裁切与替换对齐**：独立资源默认按各自渲染边界紧裁；同一槽位中重叠、尺寸相近且不会同时显示的替换资源才默认共用画布，例如 banner、立绘或列表图标的互斥版本。仅有几何重叠、属于同一父组或出现在同一列表项，不构成统一尺寸的理由。按钮文字与底图、进度条按下文的局部组件约定处理。
- **资源复用**：同一素材能通过缩放、旋转和位置变换还原的，只交付一份 PNG，在清单记录每个实例的变换和来源。尺寸、角度、坐标、外围透明留白以及变换重采样造成的像素差异，不单独构成另切一张的理由；变换后仍有内容或样式差异的版本才分别保留，具体判定见下文。
- **输出目录**：用户指定时使用该目录；未指定时，以当前工程根目录下的 `exports/` 为导出根目录，为本次任务创建一个唯一目录，例如 `exports/huo_dong_2_750x1500/`，并解析为绝对路径。所有切出的图片直接放在这个目录内，不按控件类型、画板或图层组再建子目录。
- **图片格式**：默认 PNG，保留透明通道和半透明边缘。使用稿件已有透明度，不因导出透明 PNG 而额外抠图。

先读取设计稿和已有会话约定，补齐必需信息。说明采用的缩放轴、预计尺寸和输出目录后继续切图；影响输出结果的不明确项按下文询问。

## 不明确项的澄清

- 已有用户说明、已确认约定或本 skill 默认规则能解决的问题直接执行，不重复询问。检查图层结构与预览后，仍无法判断且会影响切图结果时主动询问，例如文字是静态还是动态、哪些内容属于同一完整资源、状态对应关系、对齐组或有效裁切区域。
- 问题尽量集中提出，指出具体素材或图层、当前理解及不同选择对结果的影响；适合时提供局部预览和简短选项，便于用户判断，不仅笼统询问“怎么切”。
- 等待答复时只暂缓依赖该答案的素材，继续处理其余已明确部分。用户答复前不擅自确定该项的拆分、合并、排除或补绘方式；将其记录为待确认，与失败项区分，答复后按已确认规则继续处理。

## 分辨率适配规则

用**游戏设计分辨率**判断横竖屏，不用 PSD 的宽高判断。设设计分辨率为 `Dw × Dh`，源设计稿为 `Sw × Sh`：

| 游戏方向 | 等比缩放系数 | 缩放后的整稿尺寸 |
| --- | --- | --- |
| 竖屏：`Dw < Dh` | `s = Dw / Sw` | `Dw × round(Sh × s)` |
| 横屏：`Dw > Dh` | `s = Dh / Sh` | `round(Sw × s) × Dh` |
| 方屏：`Dw = Dh` | 默认按宽度：`s = Dw / Sw` | `Dw × round(Sh × s)` |

宽高必须是正整数，非适配轴四舍五入后至少为 1。用户明确指定方向或适配轴时遵从用户设置，并记录覆盖项。`s = 1` 时跳过重采样；`s > 1` 时允许等比放大，说明可能损失清晰度。

这里的“缩放画布”指 **Photoshop「图像大小」中连同图层内容一起等比重采样**。不能只改「画布大小」，不能将宽高分别拉伸到 `Dw、Dh`，不能靠修改 DPI 完成适配。

源稿与设计分辨率的宽高比不同时，只保证适配轴对齐；另一轴保留等比结果，不自动裁剪、补边或重新排版。切图仍按完整缩放稿的实际范围导出。

- 竖屏：源稿 `1440×3000`，设计 `1080×1920` → `s = 0.75`，整稿 `1080×2250`。
- 横屏：源稿 `3000×1440`，设计 `1920×1080` → `s = 0.75`，整稿 `2250×1080`。

先缩放整份设计稿，再在缩放结果上测量和切图；不对每张导出图重复缩放。UXP 使用 Photoshop DOM 或 `batchPlay` 的图像大小操作，锁定纵横比，并检查描边、投影等像素尺寸效果是否同步缩放。

## 执行流程

### 1. 读取并保护设计稿

1. 按工程内置 UXP 执行说明的目标文档规则，通过 UXP 一次读取目标文档的 ID、路径、像素宽高、颜色模式与已打开文档列表，明确用户指定的设计稿。
2. 使用 harness 递归读取全部图层结构、原始可见性及必要的边界、蒙版、剪贴和效果信息，并输出一次原始整稿预览；隐藏资源在工作副本中逐项显现检查，不能只按原始预览决定切图范围。
3. 复制整个设计稿作为工作文档，记录源文档与工作文档各自的 ID。后续修改显式指定工作文档 ID；保留源稿原来的图层、可见性和保存状态，不覆盖源 PSD。
4. 存在多个画板时，以目标画板的实际宽高和原点为基准，先在副本中隔离目标画板；不使用多个画板的联合外包框。多个目标画板分别适配，各自的切图仍汇入同一个输出目录。

### 2. 建立资源清单并等比缩放

- 根据用户范围、完整图层树、图层组语义、依赖和逐项预览确定切图单位，记录稳定的图层 ID 或完整层级路径，以及原中文名称。
- 图标、面板或装饰可按完整资源组导出；分类组继续向内查找。先按实际用途区分独立资源、控件组成部分和替换状态，不能将包含立绘、底板、文字和图标的整张卡片自动视为一个按钮或对齐组。组内所有静态文字与图像分离，动态文字排除；按钮拆分静态文字与底图，进度条拆分底图、填充及静态文字。避免在交付中同时输出完整合成图及其拆分子图，除非用户明确需要两种版本。
- 默认包含隐藏图层、隐藏组内的资源和隐藏备用状态；不能因原始不可见，或名称包含“备用”“参考”“标注”，就自动跳过。按文字规则排除动态内容；无可渲染像素的空层、动态文字、失败项和用户明确排除的项在清单中说明原因。
- 显现隐藏目标时，只开启该目标和必要祖先链、依赖；同一位置的其他版本分别隔离导出。遇到隐藏组继续枚举其子资源和状态，逐项制定可见性覆盖，不一次打开全部隐藏子层叠成一张图。完成后恢复原始可见性。
- 保留资源需要的蒙版、剪贴关系、描边、阴影和透明度；按钮的文字效果随文字导出，底图不包含文字。不同状态分别命名。
- 独立可见资源之间不要互相遮挡。依赖外部调整层、穿透组或背景混合的资源需结合依赖导出并检查结果；依赖范围无法确定时只询问该项。
- 只有合并后的平面稿时，按用户区域或可辨识的独立区域裁切；重叠、被遮挡或缺失的像素不能宣称已恢复成独立透明素材。
- 按适配公式对工作稿整体缩放一次，重新读取实际宽高、图层边界和预览，检查布局以及图层效果是否同比例变化。

#### 静态文字独立导出与动态占位

- 先按控件语义和用户说明将文字标为 `static`、`dynamic` 或 `mixed`，落实到字符片段，不仅按整个图层判断。固定标题、说明、标签和按钮文案作为静态文字；进度数值、倒计时、玩家数据、数量、分数等由代码变化的字段作为动态文字。不仅凭存在数字或文字颜色来判断，固定编号也可能是静态文案；影响交付且无法判断的字段单独询问，其余先完成。
- 每份独立静态文字保留自身描边、阴影及原位置，导出透明 PNG；文字与标题装饰、图标、面板、按钮底图等图片分别导出。构成同一文字表现的填充、描边和阴影层可合为一份，不把装饰合入文字。
- 动态文字不生成 PNG，也不烘焙到其他图片。整层动态文字直接排除；同一句或同一完整混合文案只去除动态片段，其余静态内容导出为**一张 PNG**。例如 `通关 15/15 关，领取宝箱` 导出 `tishi.png`，两侧静态文字都在图内，仅原数字区域透明；不能按动态区两侧拆成多张图。不能删掉字符后让文字重新排版、拼接或居中，也不把可变长数字替换成等数量空格来假定位置不变。
- 在工作副本中通过文本片段、蒙版或经核实的裁切区域处理动态内容，保持静态字形、效果、基线和相对坐标；处理中产生的静态片段只作临时组成层，交付时合为一张完整文案 PNG。使用原文案的完整区域，默认维持已有画布，不逐段紧裁，也不因动态区留空而缩小画布、改变锚点。
- 动态占位通过清单的 `runtime_text` 记录：来源层级/ID、原文或示例值、字符范围、原稿与缩放稿中的区域、对齐方式、可读到的字体/字号/颜色/样式、判定理由及相关静态资源。标明 `exported: false` 与 `reason: "runtime_text"`，不输出空白占位 PNG，也不将有意排除计为失败。字体信息缺失时注明，不猜测。
- 文案若烘焙在像素图或智能对象内，先检查是否有可编辑源；无法无损分离文字或清理动态内容时记录具体限制，不能把残留文字的整图当作已完成拆分，也不擅自抹除或重绘背景。

#### 按钮文字与底图拆分

- 为每个按钮建立 `底图 + 静态文字层/文字组` 的资源关系。导出底图时隐藏该按钮的全部文字；导出某份静态文字时只保留该份文字及其必需效果，不把按钮底色烘焙进文字 PNG。动态字段按上节排除并保留占位。
- 多个文字图层若共同构成同一段字的填充、描边或阴影，将这些表现层合为一份文字资源；不同静态文案、状态或独立标签分别导出。隐藏的按钮、静态文字版本也包含在内。
- 已确认属于按钮本体的底图和按钮文案采用按钮的局部共同区域，保留文字的原始位置，通过透明留白保证中心锚点一致。这是按钮组件的配套画布约定，不扩展到同一父组中的独立图标、立绘、提示或整张列表卡片；按钮状态是否共用区域仍按下节的互斥替换条件判断。
- 若文字已与底图合并到不可分离的像素层，标明无法无损拆分并说明具体资源；不能将有文字的整图标成“无文字底图”，也不擅自抹除或重绘。继续交付可完成的资源。

#### 进度条底图与填充分离

- 将轨道底色、边框等静态部分组成无进度、无文字的底图，将实际进度颜色、纹理和自身效果组成独立填充 PNG；静态标签单独切图，动态数值（如 `26 / 38`）排除并记录占位。隐藏的进度状态也分别处理。
- 填充依赖底层形状的剪贴或蒙版时，在临时副本中保留或转换该依赖，使满进度填充单独可见且符合轨道轮廓；不能把不透明底色烘焙进填充 PNG，也不能仅隐藏剪贴基底后将空图算作成功。
- 默认按 **100% 满进度** 导出：根据轨道有效内部区域确定满进度起止位置，不把共同 PNG 画布的透明留白或边框算作填充范围。填充方向以控件本身为准，与游戏横竖屏无关。
- 在工作副本中扩展可编辑形状或蒙版，保留厚度、圆角半径、颜色、纹理和效果，避免直接横向拉伸圆角端帽、描边或图案。纯色填充可复用轨道内部形状并应用原填充样式；复杂纹理无法可靠延展时记录具体限制，不擅自重绘。只有用户明确要求原始进度时才按原稿长度导出。
- 底图、填充及所属静态标签使用进度条的局部共同区域，保留原始位置及透明留白；不把附近的独立图标或面板并入。替换状态按下节条件分组。动态数值不导出，也不因填充满格而改成固定 `100%`。清单记录 `fill_mode: "full"`、`fill_fraction: 1`、轨道满进度区域和扩展方式；原始进度模式记录为 `source`。
- 在工作副本中生成满进度参考，按共同中心叠放底图与填充，检查覆盖完整轨道、圆角不变形且不越过边框。满格结果不能与原稿的部分进度做全图相同比对。若只有无法无损分离的合成像素层，明确记录限制，不伪造独立填充。

#### 独立裁切与替换资源的共同画布

先检查能否复用同一素材，再判断不同内容的对齐关系和画布；不能将仅有变换差异的实例误当成替换版本，也不能先将所有相交区域取并集：

| 资源关系 | 画布处理 |
| --- | --- |
| 独立使用的图标、立绘、底板、文字或装饰 | 各自紧裁，通过清单坐标还原位置；即使相互覆盖也不自动统一尺寸 |
| 同一槽位中重叠、尺寸相近且互斥显示的版本 | 建立替换对齐组，使用共同区域和中心，例如轮换 banner、角色立绘版本、列表图标状态 |
| 按钮底图与自身文案、进度条底图与填充等本模块已约定的配套组件 | 仅在对应控件的局部区域共用画布，不向整行列表或父面板扩展 |
| 用户指定固定区域或已有明确的运行时画布约定 | 遵从该约定，在清单中记录依据 |

- 替换组须同时满足同一用途/槽位、位置重叠、渲染尺寸相近和互斥显示。结合图层语义、隔离预览和状态关系确认；某层在 PSD 中隐藏不能单独证明互斥，尺寸接近也不能单独证明是替换版本。比较实际内容的宽高、比例及切换后的透明留白，不用整行容器边界或统一的百分比阈值代替判断。
- banner、立绘、列表图标只是关系示例，不是按名称分组的白名单；同类素材也可能同时出现或独立使用。明显大小悬殊、可同时显示、仅有遮挡或装饰关系的资源默认分别紧裁。对齐关系不沿几何相交或父子层级传递。
- 先在缩放稿坐标系中测量组内成员独立渲染后的可见范围，包括隐藏替换版本、描边和阴影，再取并集：`L = floor(min(left))`、`T = floor(min(top))`、`R = ceil(max(right))`、`B = ceil(max(bottom))`。不同列表位置的实例先根据已确认的槽位原点换算到同一局部坐标系，保留各实例原点；不能把它们在整稿中的远距离排布取并集。用户指定固定区域时以该区域为准，并检查有无效果被截断。
- 组内未复用的独立资产导出同一坐标系的 `[L,T,R,B]`，宽高统一为 `R-L`、`B-T`，中心统一为 `[(L+R)/2,(T+B)/2]`，归一化锚点为 `[0.5,0.5]`；复用实例则通过变换接入该区域，不另存同尺寸副本。同一组只计算和取整一次，保留各成员相对槽位的像素偏移，不移动可见内容来强行居中。仅有宽高相同不能证明已对齐。
- 每组记录 `alignment_reason` 和成员关系。独立资源的 `alignment_group` 为 `null`，不因相同尺寸、相同名称或同一父组创建对齐组；检查发现小资源被补成整张卡片大小时，重新核对分组依据。

#### 重复素材去重与实例位置

- 将可复用的图片资产与它在界面中的使用实例分开。相同对话框或面板底图出现在多条列表项、不同角色或不同文案下时，先移除已拆分的文字、立绘和独立装饰，再比较底图本身；确认相同后只交付一份 PNG，各处分别引用。去重不要求实例重叠或互斥显示。
- 比较时先消除外围透明留白，并在副本或检查渲染中用缩放、旋转、位置变换将候选对齐，再核对图案、轮廓、颜色、描边、阴影、透明度和蒙版。可用负缩放表达同一素材的镜像；不能用局部变形、补绘或改色掩盖实际内容差异。全透明像素的 RGB 不参与视觉差异判断，半透明边缘仍须检查。文件哈希、尺寸或原始 RGBA 不同不能直接判为不同资源。
- 可经上述变换还原的候选必须复用；位置造成的亚像素采样、缩放或旋转产生的正常抗锯齿/重采样差异不当作新内容。结合源图层或智能对象、效果和变换后的预览复核，保留变换参数及残余差异说明。变换后仍有图案、表情、配色、固定描边厚度或遮罩内容差异时，才保留独立版本；不能仅凭“看起来差不多”合并。
- 选用能满足最大使用尺寸、内容完整且清晰的原始版本作为唯一资产，优先原始智能对象或未反复缩放的源层；不为统一比较而放大小图再另存一份。交付 PNG 保留选定资产的原始清晰度，各使用尺寸、角度、位置由实例变换表达。已导出任务复核出可复用项时，更新文件引用、清单和数量，移除交付中的重复版本。
- 清单保留唯一资产和全部实例映射，每个实例记录来源层级/ID、控件或状态、原稿裁切区域及 `transform`：资产内的 `pivot_px`、缩放稿中的 `position_px`、`scale: [sx,sy]`、`rotation_deg`。坐标沿用 x 向右、y 向下，角度以顺时针为正；顺序为以 pivot 为原点缩放、旋转，再放到 position。需要矩阵时记录 `[a,b,c,d,tx,ty]`，明确 `x'=a*x+c*y+tx`、`y'=b*x+d*y+ty`，并将裁切原点和锚点偏移计入平移。
- 复用项指向 `reused_from` 和实际文件，不输出空白替代图，不保留“已弃用”的重复 PNG。复用不要求实例重叠、尺寸相近或互斥显示；不同对齐组也可引用同一资产，由各实例变换还原其画布中心和内容偏移。分别统计唯一 PNG 与使用实例数量。

### 3. 简洁拼音命名

在写出图片前统一生成名称映射，按以下规则处理：

- 使用简短、符合用途的拼音主名，全小写、不带声调，词内音节连写。例如背景 `beijing.png`、标题 `biaoti.png`、宝箱 `baoxiang.png`、关闭按钮 `guanbi.png`；不重复界面名、完整文案、图层路径或原稿图层编号。
- 已确认的替换对齐组和配套组件共用一个短主名，以后缀区分。例如四张建筑替换版本统一为 `jianzhu_01.png` 至 `jianzhu_04.png`，不分别拼接不同的长标题和“备用”描述。独立资源按自身用途命名；复用资产使用中性主名，不因每个角色或列表项另存一份底图。
- 同组不同状态默认用两位数字后缀 `_01`、`_02`；先分配原始可见的主状态，其余按源图层顺序分配，保持稳定顺序。已有明确且简短的用途后缀时可使用拼音后缀。
- 拆分按钮的底图和静态文字共用主名与状态编号：`anniu_01.png` 为第一份底图，`anniu_01_zi.png` 为其文字；第二份对应 `anniu_02.png`、`anniu_02_zi.png`。同状态还有多份独立静态文案时用 `_zi_01`、`_zi_02` 区分。标题装饰与文字可用 `biaoti.png`、`biaoti_zi.png`；一条混合提示文案使用 `tishi.png`，仅动态区留空，不按左右片段加后缀拆图。进度条底图、填充用 `jindu_di.png`、`jindu_tian.png`，仅有静态标签时才另出 `jindu_zi.png`；有多个状态时在主名后加入相同状态编号。
- 下划线只用于分隔必要的主名、状态和用途，不逐音节分隔。保留已有有意义的 ASCII 英文和数字，英文转小写；空格、连字符和其他标点归一为 `_`，合并连续下划线并去除首尾下划线。`ü` 写作 `v`，多音字按上下文读音处理。
- 同名时优先追加短用途或序号，不扩展成长层级名称；为同组主名解决冲突时同步调整整组。无法识别内容时使用 `ziyuan_01.png` 等短名，并在清单注明。
- 原始中文名、图层路径、状态含义和底图/文字对应关系完整保留在清单中，文件名只承担简短识别作用。统一生成整批名称并判重后再写出。
- 最终文件名须匹配 `^[a-z0-9]+(?:_[a-z0-9]+)*\.png$`。避开系统保留名；所有名称按大小写不敏感的方式判重，同时检查输出目录内已有文件，自动使用未占用名称，不覆盖已有资源。

### 4. 同目录导出

- 在工作副本中记录基线可见性、逐资源的显示/隐藏覆盖和依赖映射，逐项隔离资源；优先复用工作副本，并仅为裁切或合成创建必要的临时文档。每项结束恢复基线，导出后关闭临时文档。复杂蒙版、剪贴或跨组依赖难以完整保留时，才为该资源复制完整工作文档。
- 独立资源按实际可见像素边界裁去外围透明空白，避免裁掉阴影、描边、外发光或半透明像素；使用渲染后的可见边界验证，不直接把未经核实的图层 `bounds` 当作最终裁切框。位置关系用坐标记录，不靠扩成父组画布保存。
- 已确认的替换组、局部配套组件、用户指定区域和固定尺寸背景使用各自约定区域，保留必要透明留白；未复用的同组资产不单独再裁边。记录裁切前左上角坐标，以便还原布局。重复资源复用已验证的 PNG，通过实例变换还原各自的位置及约定区域。
- 输出为 PNG，保留 Alpha，并在首次写出时设置无损压缩；不在导出后逐张重新打开 Photoshop 文档压缩，不额外缩放、不拉伸到 2 的幂次，不将原本有色背景擅自变为透明。需要 RGB/8 位转换时只在导出副本上处理并检查颜色。
- 文件路径统一使用同一个输出目录和已分配的拼音文件名。PSD 副本、临时文件和检查用预览不混入交付图片。
- 同目录写出 `qie_tu_qing_dan.json`：记录实际执行方式、设计分辨率、源尺寸、实际缩放尺寸、适配轴、比例、资源原名及层级/ID、文件名、PNG 宽高、缩放稿中的裁切区域、成功或失败状态，以及主要阶段耗时。坐标以缩放稿或目标画板左上角为原点，`x` 向右、`y` 向下，单位为像素；多画板时逐画板记录尺寸和比例。
- 清单同时记录每个资源的 `original_visible`、包含祖先可见性后的 `original_effective_visible`、`role`（例如 `static_text`、`button_text`、`progress_background`、`progress_fill`）、所属控件/状态、`crop_mode`（`tight`、`shared` 或 `fixed`）、`export_box`、`center_px` 和 `pivot: [0.5,0.5]`；对齐组另记 `alignment_group`、`alignment_reason`、`shared_export_box` 和坐标系，局部坐标须关联实例原点。复用实例记录 `reused_from`、实际文件、资产实际尺寸和完整 `transform`，原稿实例区域不能冒充 PNG 实际宽高；文字另记 `text_type` 及片段对应关系。动态文字加入 `runtime_text`，不列为成功 PNG。所有可见及隐藏节点须能对应到唯一资产、复用实例、组成层、依赖、动态排除项或失败原因；混合层同时关联静态资源与动态片段，整层动态允许 `files: []`，必须有排除原因和运行时文字记录。

### 5. 检查与交付

- 在 Photoshop 外集中核对唯一 PNG 数量、使用实例数量、文件实际存在、PNG 格式与尺寸、Alpha 通道、同一父目录、拼音命名和重名处理；对照清单检查漏图、空图和重复导出，包含缩放、旋转、平移后可复用的候选。重复素材须能追溯到同一资产及各自完整变换，引用不得悬空；保留的相似版本注明变换后仍存在的内容/样式差异。避免仅为基础检查重新打开 Photoshop 文档。
- 将完整图层树与清单对照，确认隐藏层和隐藏组内资源已处理；检查按钮底图没有残留文字、文字 PNG 没有按钮底色。按相同中心叠放按钮底图和文字，验证能还原对应状态。
- 检查所有静态文字均与装饰/底图分开，动态文字未出现在任何 PNG 中。每条混合文案只交付一张 PNG，检查动态区域透明，两侧静态内容同时存在，位置、基线和间距保持不变；与原稿比较时排除有意留空的动态区域，并核对清单中的运行时占位信息。
- 检查进度条底图不含填充和文字，填充 PNG 非空且不含轨道底色；默认检查填充覆盖轨道 100% 有效长度，按共同中心叠放并对比工作副本中的满进度参考，核对圆角、厚度、蒙版及透明边缘。原始进度模式才与原稿长度比较；进度文字单独检查，将实际差异或无法无损拆分的限制记入清单。
- 先复核分组依据：替换组应满足同槽位、重叠、尺寸相近与互斥显示；配套组件只覆盖对应控件。独立资源不应带有无依据的大块透明留白。未复用的组成员核对 PNG 画布一致性；复用实例则按资产尺寸、transform 和组区域验证实际叠放/切换结果，不能为凑齐同尺寸 PNG 重复输出资产。原始整稿的像素比对仅使用原本有效可见的状态，额外隐藏版本单独验证；满进度等主动转换区域按转换后参考检查，其余区域与原稿比较。
- 打开代表性的导出图检查透明边缘、蒙版、文字、图层效果，以及至少一个隐藏版本和一个拆分按钮；发现视觉差异时修正相应切图再交付。
- 遇到部分失败，保留已成功资源并在清单列明失败项及原因。UXP 通过本次运行 ID、进度与完成状态判断脚本是否结束；外部等待超时不代表 Photoshop 中的脚本已终止。确认前次执行结束后，仅补跑未完成项，不直接重跑整批或覆盖结果。
- 恢复源文档为当前文档，只关闭本次创建且已完成用途的临时文档。工作副本是否保留取决于用户是否需要检查适配稿。
- 最后告知：设计分辨率、横竖屏及适配轴、缩放比例、实际整稿尺寸、唯一 PNG/复用实例/失败数量、输出目录和清单位置。未实际写出并检查的图片不能报告为导出成功。
