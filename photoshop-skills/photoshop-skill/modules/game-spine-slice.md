# 游戏 Spine 切图

将 PSD 中可独立运动、变形或替换的部件导出，供 Spine 绑定和制作动画。使用本工程的 [通用 Photoshop 模块](photoshop.md) 执行渲染。先读该模块，再根据本规范生成 UXP 任务；不继承 UI 切图的屏幕适配、文字拆分或所有部件共同画布规则。

## 默认交付与输入

- 用户给出的 PSD 或明确的当前文档；如提供现成 `.spine`、图片目录或图集，作为命名、比例、部件划分和版本的参考。案例路径仅是参考，不是每次运行的默认输入。
- 默认原尺寸 `scale = 1`，不要求游戏屏幕分辨率。用户指定倍率或角色目标高度时才统一等比缩放；目标高度用基准姿态角色主体的有效范围计算，不用整张多姿态排版宽高，不计特效和参考背景。记录测量范围与实际比例。
- 未指定目录时，在工程 `exports/` 下创建唯一任务目录：`<task>/images/` 放全部角色 PNG；任务根目录放 `spine_manifest.json`、`previews/` 与可选的 `spine_import.json`。不把预览、背景参考、临时 PSD 放入 `images/`。
- PNG 为 RGB、8 位通道、带直通 Alpha 的无损图片，保留半透明笔触和颜色。默认紧裁后四边各加 **2 px 透明边**（缩放后像素）；不预乘 Alpha、不烘焙底色、不预旋转或单独拉伸部件。
- 默认包含隐藏的动画部件、替换表情和动作；背景、排版底色、原点标记和参考整图记录为 `excluded` 并写理由。无法识别的大面积层先检查预览，不能只按名字或隐藏状态过滤。
- 默认交付切图和可复原原位的清单。已知目标 Spine 版本、插槽关系和各姿态原点时，同时生成初始摆位 JSON；信息不足时先完成 PNG 和清单，仅澄清受影响的映射。初始摆位只有 root、slots、region attachments，不等于绑定完成或已制作动画。

## 资源划分

以运动关系划分，不按图层数量机械导出，也不将分类组一键合并。

| 部位 | 默认处理 |
| --- | --- |
| 头与脸 | 脸底、眉、眼白、瞳孔、眼线/眼皮、嘴尽量保留现有独立层；左右眼或眉已分层时分别保留。 |
| 头发与配饰 | 前发、后发、刘海、长发束、呆毛、飘带、发饰分别保留，便于摆动与前后遮挡。 |
| 躯干与衣服 | 头、颈、躯干、腰带、前后裙片、袖子、披风等按现有可动部件拆分。 |
| 肢体 | 上臂、前臂、手、大腿、小腿、鞋按已有分层独立导出；手势与弯曲肢体作为替换件。 |
| 道具与特效 | 可独立运动的道具、爱心、闪电、烟雾等独立；纯参考或说明文字不混入角色纹理。 |

- 单个可动部件的颜色、线稿、纹理、局部阴影和剪贴层可合成一张；需要不同骨骼、网格或遮挡顺序的内容分别导出。
- 源稿没有分层的左右眼、整只手或肢体不擅自分割；检查是否存在智能对象、蒙版或其他姿态可用源。缺失结构记录 `needs_redraw`，用户要求补绘时再处理。
- 保留被其他部件遮住的原始像素及关节搭接。透明 padding 不能弥补肩、肘、膝、颈、发根的缺画；检查转动或变形时是否可能露缝，并标记缺画位置。不擅自生成不存在的背面、关节或遮挡区。
- 左右沿用明确的源稿/已有项目约定，并写入清单；新命名默认角色自身左右。无法确认时暂留源名，不按屏幕左右猜测。

## 表情、动作与多姿态排版

1. 递归枚举可见与隐藏层，记录自身可见性及包含祖先后的有效可见性。在工作副本中逐项显现隐藏部件；不能一次打开所有表情合成一张图。
2. 默认以“初始/默认”姿态作为 setup pose；没有明确默认时，选正常站立且身体完整的姿态并记录理由。多姿态排版需为每个姿态分别确定原点与对齐依据，不能将它们当作同时出现的多个角色。
   原点优先沿用用户/既有项目约定，其次使用明确的原点标记或导入参考线；新角色默认取基准站姿双脚接地线的中点，忽略影子和特效。无脚物件用主体有效范围的底边中点；每个姿态寻找同一语义参照，记录实际坐标。无法可靠对应的姿态先导出并保留排版坐标，标记对齐待确认，不强行套用整张排版的中心。
3. 同一位置、互斥显示的嘴型/手势等映射为同一 `slot` 下的不同 `attachment`。默认只激活基准件；仅在特定动作出现的部件保留附件但 setup 不激活。原始隐藏不等于永远不导出。
4. 同时存在的左/右眼、眼白/瞳孔、前/后裙片、前/后发束必须是不同 slot。不能因为名字相似或位置相交就塞入互斥 slot。
5. 整套服装/角色外观的替换才考虑 skin；普通眨眼、口型、手势默认附件切换。下面的生成器只处理 default skin；需要多 skin 或骨骼、网格、clipping 时另按目标版本编写，不默默展平成错误的替换关系。
6. 不强制每种姿态导出完整重复角色。相同部件只有经像素、蒙版、效果、比例和对应关系核实后才复用，同名并不足以判重；不同的头发和衣褶等要保留。清单中记录所有源节点去向。
7. 平移对齐用共同的稳定躯干/脚底参考点，不逐张以可见包围盒中心对齐。某姿态存在旋转或比例差异时，简单减原点不能恢复到默认骨架，标明需要在 Spine 调整；不捏造相同锚点。

## 原位、裁切和命名

- 先在整份工作副本中统一缩放，再测量各隔离渲染的 Alpha 范围，包含阴影、描边和半透明边缘。`floor(left/top)`、`ceil(right/bottom)` 后添加 padding，记录最终 `export_box = [L,T,R,B]`；实际 PNG 尺寸必须等于 `[R-L, B-T]`。
- 裁切框可超出原画布；在临时副本扩展透明画布以保留外溢像素和四边 padding，扩展造成的偏移须换算回原来的缩放稿坐标。不要直接裁掉画布外的头发或效果。
- 各部件可以紧裁成不同尺寸，靠裁切框和原点恢复位置。仅在用户要求、对既有 mesh 换图、或已有固定画布约定时使用共同导出区域，不能事后再次 trim 或居中。
- 记录的所有 `export_box` 与 `poses[pose].origin` 均在**缩放后整稿坐标系**，左上原点，x 向右、y 向下；可为负数或半像素。源稿坐标另存 `source_box`，不混用。
- Spine 初始导入将所有 slot 挂到无变换的 root：`x = (L+R)/2 - Ox`，`y = Oy - (T+B)/2`，`width = R-L`，`height = B-T`。尺寸与坐标已经缩放，不再乘一次倍率；不能取整 attachment 中心丢掉半像素。
- 新资产用短小、稳定的小写 ASCII 拼音/英文名，例如 `cs_lian.png`、`cs_yanzhu_l.png`、`kx_zuiba.png`、`dp_youshou.png`。同部位用稳定 slot 名，状态前缀用于附件名/图片路径。数字只用于无法进一步区分的同类分段。
- 对接已有项目优先保留**准确大小写、路径、名称和尺寸**，例如案例的 `CS_lian` 不改成 `cs_lian`。Windows 不区分大小写仍须按目标路径精确核验。新名避免空格、路径穿越、系统保留名；整批分配并按大小写不敏感判重，不能覆盖同名图片。
- 更换已有 Spine 项目图片需同时核对旧 PNG 画布、内容位置、附件变换、网格 UV/权重和图集 trim offset。原位清单不能保证任意新紧裁图与旧 mesh 直接兼容。先输出新目录及差异；仅在用户要求更新资产时写入现有目录。

## Photoshop 批处理

读取 UXP 的[运行说明](../references/running-scripts.md)，使用内置启动器执行任务正文。先读源文档的完整结构、原始合成预览、蒙版、剪贴和效果依赖；复制整个源文档作为工作文档，重新建立层 ID 映射，只在副本中缩放、切换可见性、合成和裁切。

预先建立每项的显示/隐藏覆盖、依赖、导出框、文件名、pose、slot、attachment、setup 和后到前的 draw order。复用工作副本；每项从基线隔离目标和必要祖先链，排除背景及兄弟替换件，保留目标自身效果。需要眼白裁切瞳孔等依赖时，将遮罩转换为该部件自身的 Alpha 或明确记录运行时 clipping 需求，不能带出整个脸底、也不能丢掉遮罩而扩大瞳孔。

透明 PNG 中已烘焙图层/组不透明度时，导入 slot 保持默认白色全不透明，避免再次衰减。Photoshop 跨部件混合/调整层不能全部烘焙到每一片；不能可靠复原的依赖单列限制。需要保留 Spine 特殊混合时，逐 slot 明确指定并比较合成；生成器只接受显式的 normal/additive/multiply/screen，同 slot 的替换件须一致。

PNG 首次写出即无损压缩。先写到 UXP 本次 run folder，再由启动器集中收集到交付目录；每项恢复基线，按项记录失败。读取匹配 run ID 的最终状态，外部超时后收集同次运行，不重复启动。恢复原文档的可见性、保存和打开状态，只关闭本次临时文档，不覆盖源 PSD 或参考 `.spine`。

## 清单、导入与验收

清单结构和命令见 [交付数据约定](../references/spine/delivery.md)。有案例或要对接存量资产时，先读 [女主案例](../references/spine/main-girl-example.md)。

- 每个源节点都有 exported、dependency、reused、excluded、pending、needs_redraw 或 failed 去向与理由；待确认和缺画不报成功，也不因图片未进入旧图集而漏导。
- 集中核对 PNG 可打开、尺寸、Alpha 非空、padding、名称唯一、源范围覆盖率。按源 draw order 及 `export_box` 复原基准姿态，与相同缩放后的隔离参考图比较；隐藏替换件另做联系表和替换预览，不混入 setup 合成。
- 检查关节搭接、眼口、发丝、袖口、鞋底及半透明边缘。接缝测试可在检查副本临时小幅转动；不把这种演示称为成品动画。
- 生成 JSON 后在目标版本 Spine 的 Import Data 中新建测试骨架，核对图片路径、原位、draw order、默认显示与替换件。不把所有 PNG 拖入场景造成位置丢失。若没有可用 Spine，明确仅完成结构与静态重建验证，导入实测待验证；不把 JSON 改扩展名伪装成 `.spine`。
- 交付说明源稿、比例、基准姿态、原点、成功/失败/待确认数、目录、清单和导入验证状态。仅用户要求制作动画时才继续绑定、网格、权重、IK 和关键帧制作。

调用示例：`使用 $photoshop-skill，将 D:/art/hero.psd 按原尺寸切为 Spine 动画部件，包含隐藏表情和动作替换件，输出到 D:/exports/hero；目标 Spine 3.8.99。`
