# UXP 批量切图工作流

这是游戏 UI 切图的默认执行方式。先读取工程内的 [Photoshop UXP 执行说明](../../modules/photoshop.md)，编写任务正文，再用 [run_uxp.py](../../scripts/run_uxp.py) 与内置 [harness.psjs](../../assets/harness.psjs) 组合执行。按需读取 [运行方式](../running-scripts.md)、[结果回读](../reading-results.md) 和 API 参考，无需安装工程外的同名 skill。

## 执行入口与结果

- 使用内置启动器运行 `.psjs`。Windows 自动发现当前 Photoshop 进程的可执行文件，macOS 使用应用打开事件；不把 `.psjs` 当作 Node.js 脚本执行。
- `.psjs` 已处于 modal 环境，直接调用 DOM 或 `batchPlay`，不再套 `core.executeAsModal`；只有 UXP 插件执行方式才按插件要求创建 modal scope。
- UXP 代码使用 `require("photoshop")` 和 `require("uxp")`；文件读写通过 UXP storage 的 entry/token 完成。不混用 ExtendScript 的 `File`、`Folder`、`UnitValue`。
- 用本地文件工具将用户指定的目录或工程根目录下的 `exports/` 解析为最终导出根目录，再为本次任务创建唯一目录。UXP 可先将素材写到 `await getRunFolder()` 下的 `exports/` 文件夹，由启动器一次收集后再统一放入最终目录，避免任意输出路径的访问提示。确认源文件访问成功后再执行整批切图。
- 为本次运行生成唯一 `run_id`，将结构、预览、进度和完成结果写到本次任务的独立临时目录。只读取匹配运行 ID 的结果，避免把上次 harness 的 `state.json` 当成本次成功。

## 设计稿分析

一次读取源稿的文档信息、全部嵌套图层（包括隐藏祖先下的节点）、原始可见性、蒙版与剪贴依赖，并通过 harness 输出原始整稿预览。隐藏资源在副本中逐项显现检查；不能按 `visible` 过滤待处理列表。明确目标文档和资源范围后生成任务清单，不在循环内让模型反复决定图层语义或拼音名称。

遇到已有约定和默认规则无法解决、且会影响输出的疑点，按[UI 切图模块](../../modules/game-ui-slice.md)的“不明确项的澄清”询问用户。批处理清单中将相关素材标为待确认，只运行已明确的资源；获得答复后补跑相关项，不重复导出已完成资源，也不把待确认项记为失败或成功。

任务清单至少包含：

- `source_document_id` 或源文件路径、`design_width`、`design_height`、`fit_axis`、统一输出目录。
- 每项资源的原名、图层 ID/完整路径、原始可见性、必要依赖、预先判重的拼音短文件名，以及需要显示的目标/祖先和需要隐藏的兄弟版本。
- 每份文字及混合层内的字符片段先标为 `static`、`dynamic` 或 `mixed`。每份完整文案单独列为一个导出项，不与标题装饰、图标或底图合并；混合文案仅将动态区域留空，其余静态内容共用一张 PNG，不按左右片段分别列为导出项。动态文字不生成 PNG，加入 `runtime_text`，记录来源、示例值、字符范围、占位区域、样式及排除理由。动态隐藏层也排除，不能记为漏图或失败。
- 按钮底图与各份静态文字分别列项，标明 `button_background` 或 `button_text`、所属按钮/状态。底图排除全部文字，静态文字项排除底图，保留文字自身的效果。
- 进度条底图、填充和静态标签分别列项，标明 `progress_background`、`progress_fill` 或静态文字角色；动态进度数值仅记入运行时占位。填充默认转换为覆盖轨道有效内部区域的 100% 状态，记录 `fill_mode: "full"`、`fill_fraction: 1`、轨道满进度区域、剪贴/蒙版依赖与转换方式；用户明确要求原始进度时才保留原始长度。底图不含填充和文字，填充不烘焙轨道底色，导出组件共用区域与中心。
- 对齐组 ID、各成员渲染范围、共同导出区域、中心和锚点；按钮的底图/文字、重叠的替换图和动画帧使用一致画布。具体计算遵从[UI 切图模块](../../modules/game-ui-slice.md)的“重叠素材的共同画布”。
- 是否保留固定区域，以及拆分资源时的剪贴和布局关系。混合文字层同时关联静态 PNG 和动态占位，动态区域保持透明，两侧文字不重排。所有节点必须有去向；整层动态允许 `files: []`，须关联运行时文字记录及排除原因。

名称分配在脚本启动前或批处理开始时统一完成：同一对齐组共享短主名，用状态/用途后缀区分；例如 `jianzhu_01.png`、`jianzhu_02.png`，按钮配对使用 `anniu_01.png`、`anniu_01_zi.png`，标题使用 `biaoti.png`、`biaoti_zi.png`，一条混合提示文案使用 `tishi.png`，其中仅动态区域透明。进度条使用 `jindu_di.png`、`jindu_tian.png`，仅有静态标签时才导出 `jindu_zi.png`。原名和完整关系留在清单中，避免写出后再批量改名。文档复制后重新映射图层，不能假定源文档的 ID 在副本中保持不变。

## 一次批处理完成导出

1. **保护源稿**：复制一次完整工作文档，后续修改绑定工作文档 ID，保留源稿的图层、可见性和保存状态。
2. **整稿缩放**：按[UI 切图模块](../../modules/game-ui-slice.md)的公式缩放一次；同时处理描边、投影等像素尺寸效果，记录实际宽高和比例。发现效果未同比例变化时只修正相关效果，不二次缩放整稿。
3. **记录基线**：缓存缩放后的图层映射、原始可见性和必要依赖。每项从基线应用资源清单的显示/隐藏覆盖，开启隐藏目标所需的祖先，排除同位置其他版本；不因为保留基线就漏掉隐藏资源，也不将所有隐藏层同时打开。结束后恢复基线。
4. **按资源渲染**：全部静态文字、无文字底图和装饰分别隔离；动态文字排除，混合行通过经核实的片段或蒙版保留动态区域的透明空白，静态内容合为一张文案 PNG，处理中间片段不单独交付，不删除字符后让静态文案重排。保留各自必要的祖先链、蒙版和效果。进度填充默认在副本中扩展为满轨道，保留厚度、圆角半径与纹理；纯色形状可复用轨道内部形状并应用原填充样式，不直接拉伸圆角端帽，不将动态数值改为固定满格文案。剪贴填充不能只隐藏基底；在临时副本中保留或转换蒙版依赖，并验证填充非空且无轨道底色。优先复用工作副本，仅为合成、裁切创建必要的临时文档；复杂依赖无法完整保留时，为对应资源复制完整工作文档。缓存各对齐组成员渲染后的 Alpha 范围，包含隐藏静态资源和文字效果；在写出组内第一张 PNG 前确定整个组的共同区域，可复用临时渲染减少重复操作。
5. **裁切与写出**：对齐组成员严格按同一 `[L,T,R,B]` 导出，保留透明留白与原稿中的相对偏移；共同中心为 `[(L+R)/2,(T+B)/2]`，锚点为 `[0.5,0.5]`，不移动像素内容来强行居中，也不逐张紧裁。无对齐关系的资源才按各自渲染后的 Alpha 边界裁切。第一次 PNG 导出即配置无损压缩，记录实际尺寸与裁切原点。
6. **逐项记录**：每项完成后写入成功文件名、尺寸、裁切框或失败原因，清理该项临时文档。必要的进度写出在同一脚本内进行，不中断整个循环等待外部工具读取。
7. **结束与交付**：写出 `qie_tu_qing_dan.json` 和带 `run_id` 的完成状态，再通过 harness 输出最终预览与状态。恢复源文档为当前文档，保留适配工作稿供检查；只清理本次创建的临时文档。

使用 DOM 处理有明确 API 的操作，缺失部分使用 harness 的 `bp`/`readback`。`bp` 默认遇错记录并抛出；逐项容错模式应捕获对应资源的异常并记录失败，不能仅凭循环继续执行就写成成功。

## 集中验证与耗时

- 在 Photoshop 外一次检查全部 PNG 的存在、尺寸、透明度、文件名和目录关系；生成联系表查看复杂资源、按钮文字及透明边缘，不把整批图片重新导入 Photoshop 做基础验证。
- 核对隐藏图层及隐藏组的处理覆盖率、所有静态文字与底图/装饰的分离情况，以及每个对齐组的尺寸/区域/中心/锚点一致性。拆分按钮按共同中心重叠后应还原静态部分，隐藏备用版本单独检查；动态排除项必须有运行时占位记录，不能当作失败或漏图。
- 将进度条底图与填充按共同中心叠放，检查填充覆盖轨道 100% 有效区域，并与副本中的满进度参考比较圆角、厚度、剪贴边缘和效果；仅在用户要求原始进度时比较原稿长度。确认底图无填充、填充无底色、静态文字另存、动态数值未导出。每条混合提示文案须为一张 PNG，动态区域透明，两侧静态内容完整，字形、位置、基线及间距不变。
- 保留一次缩放稿参考预览，按清单坐标使用原始有效可见状态重建布局，不将隐藏备用资源叠入原始参考。满进度等主动转换区域使用转换后的参考，动态占位区域检查透明留空，其余区域与原稿比较。只修正有实际差异的资源，已确认正确的资源不重复导出。
- 记录分析、缩放、导出与验证各阶段耗时，以及完整文档复制次数。没有同源稿实测时，不声称固定加速倍数。
- 外部启动器返回或等待超时，都不能单独证明脚本完成。读取本次运行进度与完成标记；前一脚本尚未结束时，不启动另一份脚本操作同一文档。
- UXP 入口不可用时检查 Photoshop 进程、脚本路径和启动器错误，修正可恢复的问题后继续；无法恢复时报告阻塞点。不能因为没有即时看到结果就重复启动，避免任务重叠执行。
