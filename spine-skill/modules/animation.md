# 动画制作

先读取 [工程通用](project.md)。根据目标动作选择已有基线、主姿势设计或模板草稿；绑定或权重需要变化时补读 [骨架绑定](rigging.md)。

新动作在主姿势阶段检查素材能否覆盖目标活动范围，制作后检查节奏和跟随；缺画、穿插或生硬时读取 [防穿帮与动作优化](motion-quality.md)，完成问题定位、修复和同帧复验。用户要求补图或改善动画质量时，必要的素材修复纳入流程，不以模板草稿作为最终效果。

## 制作前交互预览与用户验收

采用用户于 2026-11-11 明确的流程：**先直接制作最终视觉效果预览，用户验收后，Spine 按该效果复刻。** 预览在 Spine 制作之前完成，可用 GIF、无损帧动画或交互帧播放器；不要求先做好 Spine 再导出预览。默认使用便于暂停、逐帧和慢放的交互帧播放，用户指定格式优先。

1. 查看原画、分层、现有工程和参考动作，确定外观、主姿势、时序、层次与循环。参考视频和骨架/色块代理用于内部研究；交给用户验收的画面必须是当前角色完整的最终视觉目标。
2. 直接用原画部件、必要补图和替换件绘制或合成完整动作帧。为了完成这份预览，可在工作副本中先做临时拆件、补图和画面制作，保留源稿、来源与坐标；此阶段不创建或修改目标 Spine 的绑定和动画。仅允许粗略代理表达的动作必须继续做到完整画面，不能把手形、蹄形、接合、遮挡或附属运动留待“正式再做”。具体方法见 [最终效果预览](../../spine-animation-director/modules/interactive-preview.md)。
3. 内部先审查完整播放、主姿势、极值及邻帧、接触/遮挡和循环；同时检查每个可见行为能否用独立部件、骨骼、换图或网格实现，不能提交无法在 Spine 保持轮廓/体积的视觉承诺。发现缺画或实现方式不成立，先修素材或预览，不先做完 Spine 再反过来改预览迎合实现。
4. 交给用户的是**最终效果待验收版本**。保存完整帧/图集、FPS、各帧时刻、时长、画面尺寸、透明/背景方式、原点、关键姿势、素材和版本/哈希。GIF 只作观看载体时，仍保留无损源帧作为制作基准。用户明确通过前可继续修预览，不开始 Spine 制作；用户选择播放格式、调速或未回复均不算通过。
5. 用户确认后冻结这版视觉基准及素材，开始 Spine 装配、绑定和动画。复用预览所用的部件与补图，按相同世界轨迹、姿势轮廓、换图时刻和层序实现，不能重新设计一套“风格差不多”的动作。按 [与已验收预览同帧对照](delivery.md#与已验收预览同帧对照) 修正实际结果，达到已通过的画面后再交付。

用户验收的是可见效果及其版本，不只是动作大意。纯技术修复应自行推进到匹配该效果，不重复申请同一范围批准；确需改变已通过的外观、姿势、幅度、节奏或素材时，先更新最终效果预览并取得对变更版本的确认。只读检查和播放已有工程不新增此流程；用户明确另定流程时按其要求执行。

## 分阶段制作与推进条件

制作前交互预览经用户验收通过后，新动作与整体质量优化采用以下阶段；这些是代理自行执行的制作检查，不逐阶段向用户申请批准。已有动作的局部修改在已通过的预览范围内从受影响阶段进入，保留已验证的基线；用户只要求草稿时交付相应阶段并说明未完成项，不扩展为完整精修。

以冻结的最终效果帧为制作基准，把可见姿势、轨迹、体积、接触、层次与时序映射到素材、骨骼、换图和 FFD；动作配方只辅助实现，不重新决定幅度、时间或曲线的可见结果。

同类角色的质量基线参考 [已验收人工工程](../references/accepted-production-standard.md)：先选相近的角色状态，再比较姿势与节奏。基础待机允许克制，不能把“身体必须大幅运动”当作通用要求；动作名称不同而身体、手势、视线和表情没有相应状态设计时，先修主姿势。

| 阶段 | 制作与可检查产物 | 进入下一阶段的条件 | 失败时返回哪里 |
| --- | --- | --- | --- |
| 动作设计 | 按已通过的交互预览细化动作意图、角色状态、时长、循环或衔接目标、支撑及接触关系，列出关键姿势及其时间 | 与已通过方案一致，主要发力或状态变化、关键节奏明确，可据此摆出姿势 | 实现细节不清先修设计；需要改变已通过效果时返回交互预览验收 |
| 素材与绑定测试 | 在工作副本摆目标主姿势、最大弯曲和层次交换姿势，查看纯画面及必要线框 | 当前活动范围内无明显露底、关节塌陷、错误遮挡；持物或脚底接触能维持 | 按原因修拆件、补图、枢轴、权重、约束或换图后复验 |
| 主姿势草稿 | 制作主体关键姿势联系表，标出每张对应时间；先看实际显示大小下的剪影、重心、支撑和动作方向 | 无需衣发或特效遮掩也能看懂动作，关键姿势有区分且接触可信 | 重做主姿势；不要用加帧或加衣发运动补救 |
| 主体运动 | 补必要中间姿势、弧线和曲线，正常速度连续播放主体动作；检查接触时刻及邻帧 | 动作节奏、速度变化、承重或发力成立，无非预期滑步、跳动；循环或收势符合设计 | 姿势正确但生硬则修路径与时间间距；姿势本身错误则回主姿势草稿 |
| 附属运动 | 主体通过后再加头部跟随、衣发、表情和局部 FFD，保留主体通过时的版本作对照 | 根部稳定、跟随有原因、材质区分清楚，附属运动没有破坏主动作及接触关系 | 调整局部相位、幅度或恢复；主体被改动时重新检查主体运动 |
| 最终验收 | 保存回读后重新导出，与冻结效果帧同时间、同尺寸、同取景并排及叠加查看，再连续播放 | 同帧效果匹配且 [动画验收标准](delivery.md#动画验收标准) 全部通过；零翻面不代替轮廓/体积检查 | 将偏差定位到具体时间、部位及实现，修复 Spine 后同帧复验 |

主体动作不成立时，不通过添加呼吸、眨眼、衣发摆动或特效来充当完成。主体阶段仍保留维持外形与动作含义所需的换图、约束、draw order 和纠正形变；头部主动瞄准、武器挥动等属于主动作，不能误当作可省略的装饰。检查已有动画时，可在预览副本暂时停用纯附属轨道，不删除源动画的有效轨道。

每个已执行阶段简要记录“阶段、当前快照/动画名、实际查看的预览及时间、通过/不通过/待验证、下一项修正”，放在项目根目录 `.work/` 的本次任务目录，可共用一份记录。主姿势阶段看静态姿势，主体及附属运动阶段必须看连续播放，不能用工具成功、关键帧数量或端点数据代替视觉结论。预览不可用时记录待验证，可完成独立的技术工作，但不能宣称阶段通过或动作合格。

每轮先修最影响动作含义、支撑或外形的两三个问题，再对相同时间与邻帧复验。连续两轮对同一问题无改善时重新判断是设计、素材、绑定还是时间轴原因，换修复方向；依赖缺失时保留可用版本并报告具体阻碍，不无限追加关键帧或重复烘焙。

## 选择编辑方式

输入为单张完整图片时，必须先完成拆图与部件绑定，不能直接对完整角色图做整体变换或整图网格动画。此要求同样适用于 idle；拆件未完成时继续素材流程或报告缺项，不用整图起伏替代交付。

| 需求 | 优先方案 |
| --- | --- |
| 调整已有角色动作、制作同风格新动作 | 完整复制最接近的动画，再局部修改 |
| 精确设计主姿势与节奏 | 编辑完整动画对象，或 `spine_pose_to_animation` 后补其他轨道 |
| 标准骨架的快速草稿 | `spine_generate_animation`，先核对骨骼名到角色的 `roleMap` |
| 单轨补帧或局部调整 | `spine_edit_keyframes`，时间轴使用分段数组 |
| 多骨骼、插槽和形变一起调整 | `spine_edit_animation` / `spine_batch_edit`，合并相关修改 |

模板的骨骼轴向假定不一定适用于已有角色。女主工程的现有走跑包含 IK、换图与 FFD，复用基线通常更能保持原表现。具体派生和补帧示例见 [操作工作流](../references/mcp-workflows.md)。

## 动作与时间轴

- 先在预期显示大小确定可读的主姿势与节奏，再细化曲线。待机也要有符合身份的身体动作，例如武将的承重、挺胸和持械稳定，随后才加呼吸、头部、表情与衣发；不把全图轻微摆动默认作为完成品。
- 制作 idle 时，先确定状态姿势和循环中的主要变化；呼吸型可选择吸气/回落，抚须、持扇或情绪待机按各自实际姿势与极值选择，偶发动作另定进入和返回。对照已验收匹配片段，在相同显示大小下比较胸肩、骨盆、头、手、武器和脚底。幅度依据角色性格和用户反馈调整，不套固定像素/角度；过弱时修主姿势、路径和时间间距，不只等比放大轨道，也不把缺素材解释为只能小幅动。
- 手持武器或双手接触同一物件时，先确定物件主控与手部跟随关系，用合理层级、IK 或匹配的关键帧保持接触；检查剑身等刚性轮廓，不把武器与衣料一起软化。衣发与呼吸采用不同根部、相位和恢复节奏，避免全身同步摇晃。

- 先确定重心、支撑脚、躯干和手臂的主姿势，再补头部、发梢、衣摆、表情与效果。附属运动按动作产生适量滞后与回弹，幅度结合角色比例和实际预览调整。
- 手势按蓝图选择可信的基础/替换附件，先试摆离开、展开、触碰、释放和回抱的必要姿势，再安排曲线；按 [手部与接触专项](motion-quality.md#手部与接触专项) 检查中间掌型、腕口和遮挡。发现需新手势时回到素材流程，不能继续压缩张开手来绕过缺画。
- 复制基线同时保留 `bones`、`slots`、`deform`、约束、事件和 `drawOrder`；原来没有的轨道不必补空结构。不能只复制身体旋转就假定动作完整。
- `spine_set_bone` / `spine_set_slot` 改默认姿态，动作修改应写动画轨道。动画旋转、位移是相对 setup 的偏移，缩放为倍率；原生 JSON 使用 `rotate[].angle`，单骨骼工具参数为 `rotation`。
- 批量工具的 `time` 是秒，`frameIndex` 是帧号。先确认工程 FPS；时间网格只能辅助推断，生成或预览的 `fps` 可能只是采样密度。
- 主动作可用贝塞尔缓入缓出，匀速段用线性；换图、隐藏和刻意停顿按离散节奏处理。原有阶跃和贝塞尔不一律覆盖。
- `spine_edit_animation(mode="merge")` 替换传入的整条时间轴数组；局部补帧优先 `upsert`，避免误删已有帧。
- `spine_pose_to_animation` 只生成骨骼运动，不自动继承附件、FFD、绘制顺序或约束。`loop=true` 仅补首姿势中骨骼的末帧，仍需检查其他骨骼和通道；遇重名使用工具返回的实际动画名。

## 换图、FFD 与附属运动

- setup 附件和动画换图分别处理。面部表现可能是 FFD、换图或两者结合；女主的眨眼依赖面部 FFD，走跑还依赖手部换图及绘制顺序。
- 已有 IK 的腿按原绑定工作，通常由脚部目标和身体主控配合。FK 切换和 IK mix 按动作明确安排。
- 编辑 FFD 前用 `spine_get_mesh` 确认逻辑顶点与固定点。`spine_deform_mesh` 的 offsets 为逻辑顶点数 × 2，不直接替换加权网格内部的影响数组。
- 周期飘动可用 `spine_mesh_wave`；已有动作显式选择 `mode="add"` 或 `"replace"`，保持发根、腰线和袖根稳定。
- 惯性跟随可用 `spine_cloth_motion`，先检查原动画，再选择局部方向、柔软度、固定点和位移上限。非循环动作设 `loop=false`；重复烘焙会再次累加，调参从同一源副本或备份开始。它不提供碰撞或自碰撞。
- 拓扑与权重尽量保持基线。确需重绑时按骨架模块处理现有 FFD，避免丢失其他动画的形变。

具体换图、层次、事件和网格参数见 [操作工作流](../references/mcp-workflows.md)；参考角色的组合见 [mainGirl1](../references/main-girl.md)。

## 循环与交付

循环检查首尾姿势、速度趋势、IK、FFD、附件可见性和绘制顺序；末帧数值与首帧相等仍需看接缝。单次动作按需要保持结束姿势或回到指定待机。

按工程通用模块保存和回读，再按 [预览交付的动画验收标准](delivery.md#动画验收标准) 检查动作含义、姿势重心、节奏力度、附属运动、外形层次、循环衔接和实际使用，并记录验收结论。参考工程原有循环问题不能作为新动作通过验收的依据。
