# 骨架装配与绑定

先读取 [工程通用](project.md)。已有可用 `.spine` 绑定时优先复用，只有任务需要时才重装配或重绑。

## 从贴图装配

- 一张透明 PNG 中的互不重叠散件，先用 `spine_cut_parts` 得到部件、蒙太奇和 `partsMeta.json`；查看后明确语义、父级和前后层次，再用 `spine_assemble` 的索引装配。
- 独立 PNG 目录使用 `spine_build_skeleton`。当前工具自动读取 `partsDir/partsIndex.json`，没有 `partsIndexPath` 参数；该索引格式不同于 assemble。生成骨骼默认都挂在 root 下，仍需整理层级与枢轴。
- 空工程从 `spine_create_project` 起步，再添加骨骼、插槽和附件。`spine_pipeline` 只在输入满足要求且需要预设动作全流程时使用。
- 完整人物立绘中被遮挡的肢体不能靠连通域自动补出；缺少拆件时明确所缺素材。

精确索引格式见 [操作工作流](../references/mcp-workflows.md) 的“从拆分贴图建工程”。

## 层级、枢轴与附件

1. 从关节位置和预期运动关系确定骨骼父子与枢轴，结合插槽绑定确认左右和部件职责，不凭名称数字猜配对。
2. `spine_add_bone` / `spine_set_bone` 操作 setup 骨骼；`spine_add_slot`、`spine_add_attachment` 和附件变换工具负责挂接与拼接。调整 setup 会影响所有动画，不能用它代替某个动作的关键帧。
3. 骨骼坐标按父级空间处理，附件还有自身变换。修改父级或枢轴后重新检查世界外形，不只比较局部坐标。
4. 在 setup 中检查部件位置、缩放、透明边、层次和资源路径，再建立权重及约束。皮肤或附件改名优先使用同步引用的专用工具。

沿用女主工程时参考 [骨骼与插槽映射](../references/main-girl.md)，不要将普通命名的特殊肢体资源当作冗余数据删除。

## 网格与权重

- region 转网格可用 `spine_generate_mesh` / `spine_manage_attachment(convert_to_mesh)`；修改现有拓扑用 `spine_edit_mesh`。保留贴图路径和 setup 外形，先确认任务确需替换原拓扑。
- 用 `spine_get_mesh` 读取逻辑顶点、世界位置、三角形和逐点权重。加权网格的 `vertices` 存储骨骼影响项，不能用数组长度除以 2 当逻辑顶点数。
- `spine_edit_weights` 用于绑定、设置、归一化、剪枝和平滑；选择真实影响区域，修改后确认 setup 外形与动画跟随均符合预期。
- 自动权重用 `spine_auto_weights`，需要服务端已安装 libigl BBW 求解器。缺少时报告该条件，不将普通归一化称为自动绑定。参与骨骼与固定点依据实际几何选择。
- 先保留现有网格拓扑和权重。已有 FFD 时不要为了消除报错直接使用 `deformPolicy="clear"`，它会清除该附件在全部动画中的形变；关联/链接网格还有额外限制。确需改变时先在工作副本处理，并安排恢复受影响 FFD。

参数与限制见 [操作工作流](../references/mcp-workflows.md) 的“网格、权重与衣料”。

## 约束与验收

- 根据运动需求选择 IK 或 FK，目标骨骼与受约束链分开定位；沿用工程时先检查现有约束的目标、顺序和 mix。
- 已受 IK 驱动的腿优先调整脚部目标和身体控制器；需要 FK 时明确安排 IK mix，避免大腿旋转被约束覆盖。不要把 IK 目标映射成大腿模板角色。
- 绑定后检查 setup、关节弯曲和代表性极限姿势。既有工程还要抽查受影响动作，留意塌陷、拉伸、部件漂移和穿插。
- 按工程通用模块完成保存与引用检查，再按 [预览交付](delivery.md) 检查线框和纯画面。只有初始摆位 JSON 时，不能声称已完成权重绑定。
