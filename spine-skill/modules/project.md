# Spine 工程通用

所有任务共用本模块。这里负责确定真实工程与工具能力，其他模块按需处理绑定、动画和交付。

## 开工与定位

1. 确定实际目标、动作含义、时长、循环与否及交付需求。可从现有工程和用户上下文推断的信息直接采用，并说明重要假设。
2. 发现会话中的 `spine-mcp` 工具，通常显示为 `mcp__spine_mcp__spine_*`。以下使用短名。缺少连接时检查现有配置和服务错误，报告具体缺项；不要把编写 JSON 当作已保存 `.spine`。
3. 先调用 `spine_get_capabilities({projectPath})`，再用 `spine_check_project` 体检。需要层级时读取 `spine_describe` / `spine_get_project_info`，再按需查询动画、附件和网格。当前实测支持 3.8，其他系列以能力结果为准，不通过改版本字符串绕过限制。
4. 一次导出 JSON 到工作目录，分析和预览复用该快照；写入后重新导出。检查 `skeleton.images`、实际 `images/`、atlas 页面名称及图片路径。JSON 移到其他目录后，相对图片路径不会自动指向原资源。
5. 从父子关系、插槽绑定、网格权重和线框预览确认控制对象。自动角色匹配只是线索；参考女主只有 `root` 自动匹配，不能直接套用整骨架模板。

导出分析可使用 [inspect_spine_json.py](../scripts/inspect_spine_json.py)，只读 Spine 3.8.x JSON。工具参数与快照示例见 [操作工作流](../references/mcp-workflows.md) 的“读取与快照”。

目标包含动画制作或调整时，完成只读检查后先按 [制作前交互预览与用户验收](animation.md#制作前交互预览与用户验收) 展示可操作的交互预览（默认不生成 GIF），用户明确通过后才进入制作与编辑事务。检查工程、准备预览所需的只读快照和素材分析可以先做；不能以准备工作为由提前拆件、绑定或写入动画。

## 编辑事务

- 同一工程的 MCP 写入串行执行；避免编辑器同时保存。发生外部修改冲突时重新读取，再应用仍有效的改动。
- 工具通过导出、修改和后台重建保存工程。将相关骨骼、插槽和轨道的修改合并为少量事务，避免逐骨骼逐帧反复重建。
- 多骨架工程显式选择 `skeletonName`，并使用支持该参数的编辑入口，保留其他骨架。
- 新动作优先使用独立名称和 `mode="create"`；明确要替换时再用 `replace`。复杂编辑先对同一组参数执行支持的 `dryRun`，检查后正式写入；dry-run 不执行 CLI 重建回读。
- JSON 重建只承诺可导出数据。编辑器文件夹、视图等专有状态依赖原始 `.spine` 备份；保留工具返回的备份路径。

## 每次写入后的检查

1. 检查工具错误、警告、实际目标和返回名称，不用启动成功或请求返回代替保存结果。
2. 运行 `spine_validate_references` 并重新读取受影响对象；动画检查名称、时长和目标轨道，绑定检查父子关系、附件和约束。
3. 与编辑前快照比较，确认非目标动画、骨架、皮肤和约束未意外改变。
4. 骨架或动画有视觉变化时，用 [预览交付模块](delivery.md) 的相关检查确认外形、层次、形变或循环。预览不可用时明确视觉验证尚未完成。

完成回复给出实际工程、目标对象、产物路径、验证结果及仍存在的具体问题。恢复与回滚规则见 [预览交付模块](delivery.md)。
