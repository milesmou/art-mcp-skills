# 预览、交付与恢复

先读取 [工程通用](project.md)。制作前的交互预览按 [动画制作的用户验收流程](animation.md#制作前交互预览与用户验收) 提供，用户明确通过后才开始制作；下面的成品验收不能代替该前置步骤。成品预览使用当前保存后重新导出的快照，避免用旧 JSON 或旧 `.skel` 验证新动作。

## 预览交付前审查

对本次新制作或修改的动画，先在工作目录生成检查版，完成视觉审查和必要修复，再把预览链接、画面或工程包作为本版结果交给用户。制作前方案和正式成品均执行；只读展示既有参考不重新验收原作。这是代理自行完成的制作职责，不增加一次用户审批，也不能把发现明显错误的责任留给用户。

先确定本版要表达的主体行为、关键姿势和接触关系，再完成以下检查：

1. **核对版本与实际播放。** 记录动画、时长、工程/快照、贴图/图集和预览版本。成品从保存回读后的最新数据播放；正常速度、固定取景和实际显示大小看完整动作及循环，再查看局部大图、慢放和关键帧。数值验证、联系表、首尾一致或播放器按钮可用均不能代替连续画面审查。
2. **审查动作是否成立。** 按下方动画验收标准检查角色意图、肩—肘—腕等肢体归属、姿势体积、支撑与重心、发力先后、弧线、速度变化、接触停留和收势。对照适用的已验收参考判断幅度与节奏；不能因轨迹平滑就判动作合理，也不能靠缩小动作掩盖素材问题。
3. **审查穿帮与瞬间变化。** 检查轮廓、关节搭接、露底、残片/重影、网格翻折、手物接触和前后层次。单独定位接触进入/保持/离开、最大弯曲、换图、换层及循环接缝；检查准确时刻及紧邻帧，写明工程 FPS 或采样步长。持物或触碰动作要沿完整肢体核对到接触部位，不能只看一个锚点误差。拆件后仍需连续的接合区按 [切口连接专项](motion-quality.md#切口连接专项) 查看切口两侧的世界运动，覆盖叶根、穗根、发根或衣片连接等实际受影响部位。
4. **单独审查手部。** 动作涉及手部时，按 [手部与接触专项](motion-quality.md#手部与接触专项) 分别检查两只手，查看实际显示大小和足以辨认指缝、腕口的局部放大画面。核对手指/手掌形状、腕袖衔接、抓握包裹和触碰遮挡，并逐段检查收拢、展开、翻腕、回抱的中间姿势；正常遮住的手指不要求全部显露。锚点贴合、同一附件连续或首尾一致，均不能证明手形与遮挡正确。
5. **修复后复审。** 将问题记为“动画 + 时间/帧号 + 部位 + 实际现象 + 预期 + 原因 + 修复 + 复验结果”，按 [防穿帮与动作优化](motion-quality.md) 修素材、绑定或运动。更新受影响图集和快照，复查原位置、邻帧及整段动作；比较修复前后，确认没有造成新的遮挡或姿势问题。用户再次指出漏检时，撤回受影响的通过结论，定位复验后才能重新判定，不能只补规则仍保留原通过状态。

方案代理审查其实际表达的行为、关节、支撑、接触、节奏及循环；自绘代理还按 [关节代理的连接与遮挡](../../spine-animation-director/modules/interactive-preview.md#关节代理的连接与遮挡) 检查父子连接、枢轴与局部层次。代理本身可见的结构错误仍判为问题，不能归入尚未制作的素材限制；尚未存在的正式贴图、手势或绑定注明“本阶段无法验证”，不能据代理预演宣称成品无穿帮。正式成品必须审查实际附件、贴图和形变。渲染差异须对照源贴图、编辑器或适用运行时定位，不能把尚未解释的接缝直接排除在审查外。

### 逐件与局部周期审查

多个独立小主体、活动遮挡或快速局部循环容易在整体画面中漏检。此类任务补充以下审查，局部图与整段正常播放共同作为画面依据。

- **逐件隔离并保留空间关系。** 按稳定编号查看每个独立主体，放大图需覆盖受检主体及附属件的运动范围。群体靠近或互相遮挡时，在检查副本中仅绘制当前主体及其附件，核对胸腹、末端、双翼等实际需要的结构，再返回完整构图查看原有层级。
- **检查遮挡背后的材料。** 隐藏或移开活动前件，检查目标范围内应当出现的主体轮廓和连接。再显示前件，检查展开、收拢及经过主体的中间姿态。素材问题回到 [活动遮挡下的部件完整性](../../photoshop-skill/modules/image-part-split.md#活动遮挡下的部件完整性) 处理，修复后使用最新附件与图集复验。
- **按局部周期取样。** 先从实际关键帧或播放确认振翅、旋转等局部运动的周期与相位，再选择最大展开、最小展开、转向及其邻帧。检查所选画面确实覆盖不同姿态。均分整段动画的采样间隔若接近局部周期的整数倍，需缩短检查窗口、改变采样间隔或补充逐帧慢放。例如 2 秒循环中的 10 Hz 振翅每 0.1 秒重复，每 0.5 秒取样会重复同一相位。
- **分别记录证据。** `acceptance.md` 按主体编号记录隔离完整性、局部姿态与正常播放结果，附实际时间、速度、放大条件及证据路径。原位 RGB 差异证明静态重建，引用与端点数值证明数据一致性，身体完整和遮挡正确需有对应画面证据。采样数量按当前运动与缺陷风险确定。

某件暴露批量拆件或共用恢复方法的问题时，扩查同批受影响实例，撤回这些实例及依赖它们的整体通过结论。完成逐件修复、局部周期和整段播放复验后，更新交付入口中的工程、贴图、图集与预览，保持同版。

### 关键遮挡关系审查

多个近远部件、载具、道具或衣片交叠时，从独立原稿或已确认画面中选出容易混淆的遮挡对，记录“后件 → 前件”和应露出 / 应遮住的局部。例如当前原画若表现远侧轮在车厢后、近侧轮在车厢前，则分别核对两组关系；不能把所有车轮统一放在车厢之上，也不将此例强套给其他视角。

- 核对 setup `slots` 的后到前顺序，以及各动画实际生效的 `drawOrder`；分别查看静止姿势、转动 / 摆动极值、层序键及其邻帧。近侧大件可能遮住远侧错误，需暂隐近件观察远件与车厢，再恢复全图确认。
- 在同尺寸原稿局部与实际运行时画面之间对照遮挡边界，并看正常速度播放。由同一部件列表生成的工作 PSD 和 PNG 重建图可能共用错误层序；两者像素一致只证明相互一致，仍须对照独立原稿。引用有效、无网格翻面、首尾相等均不能证明前后关系正确。
- 在 `acceptance.md` 按遮挡对写明原稿依据、实际查看时刻 / 局部与结论。修正后同步工作 PSD、清单 `draw_order`、setup / 动态层序、生成输入及实际使用的预览数据；保留原稿。只有层序变化且贴图与 region 未变时，无需重打图集。

### 结论与交付条件

- 在本任务 `acceptance.md` 记录本版的**通过 / 不通过 / 待验证**、实际观看条件、对应时间与证据。沿用后文验收维度，不用总分抵消明显缺陷。
- 明显穿插、露底、错层、残片、手脱物、触碰悬空/穿透、肢体断开或突变、机械折向、非预期换图/换层跳变及循环跳变，均判本版不通过，修复后再交付用户评审。必要的画面证据缺失则为待验证；导出成功或技术检查通过不能将其改成通过。
- 审查通过后才更新用户预览入口与交付包，确认页面、截图、图集和工程对应被审查的同一版，避免缓存或旧链接显示上一版。发生后续修改时复查受影响项和整段动作，再更新交付。
- 用户明确要求观看问题版或制作中的草稿时，可以展示并标注问题时间、未完成项与草稿身份；这不改变审查结论。工具或素材阻碍未解决时如实说明缺项，不用“待用户验收”代替尚未完成的自查或修复。

代理审查通过与用户最终验收分别记录；审查通过不等于已经获得用户认可。

## 动画验收标准

单图输入的动画先核对拆件产物和真实附件关系：按运动与遮挡分离的部件应有联系表、原位映射及对应附件。若仍以完整角色图的单个 region/mesh 制作动画，即使有多骨骼权重、FFD 或正常循环，也不满足交付要求。图集打包到一张 PNG 不影响判断，检查的是独立部件区域与附件，而非图集页数。

验收前明确动作含义、角色风格、时长、循环与否、衔接对象和交付范围。合格表示满足需求、没有影响使用的明显问题、交付可用；优秀还要求动作有重量、节奏、性格和表现力。骨骼数、关键帧数、模板生成成功或工具返回成功不作为质量通过依据。

同类角色可按 [已验收人工工程标准](../references/accepted-production-standard.md) 选择同用途、同状态的参考，在相同角色显示高度、固定取景和正常速度下比较。人工基线的通过状态来自用户确认；原始端点差异、自动模板匹配率或预览器伪影只作诊断线索，不据此否决已验收作品。新作仍需检查实际连续播放与适用的使用环境。

| 检查维度 | 合格要求 | 常见不合格表现 |
| --- | --- | --- |
| 动作含义 | 在实际显示大小和正常速度下能看懂动作，符合需求及角色性格 | 攻击像挥手、受击像鞠躬、待机幅度喧宾夺主 |
| 姿势与重心 | 关键姿势清楚，支撑、发力和重心变化可信；走跑结合角色在场景中的移动速度检查支撑脚 | 非预期滑步、脚底漂浮、失去支撑却没有相应调整 |
| 节奏与力度 | 按动作需要安排蓄力、发力、停顿和恢复，速度变化及受力反馈清楚 | 全程机械匀速、攻击无力、落地没有承重，或出现非预期抖动 |
| 身体与附属运动 | 主体带动关系合理，头发、衣摆等按材质和动作适量滞后、回弹，固定根部稳定 | 所有部件同步摆动、衣料无故飘动、跟随幅度抢过主动作 |
| 外形与层次 | 关节、轮廓、体积及前后遮挡符合设计，换图与 FFD 过渡合理 | 关节露缝、网格翻折、脸部拉坏、明显穿插或绘制顺序错误 |
| 循环与衔接 | 循环首尾姿势及速度趋势连续，IK、FFD、附件可见性和绘制顺序一致；单次动作结束和切换符合设计 | 每轮接缝顿挫、切换时跳姿势、残留表情或错误附件 |
| 工程与实际使用 | 保存回读、引用和交付资源完整；需要运行时交付时，在目标环境验证版本、贴图、混合、事件及约定的性能预算 | 未保存、丢图、导出旧动作、事件错位、运行时效果异常或超出预算 |

- 明显破图、动作含义错误、非预期循环跳变、资源缺失或目标运行时无法使用等问题必须修正，不能用其他表现项抵消。
- 按预期显示尺寸正常播放，检查主动作是否可读、是否达到用户要求的幅度；idle 不能只凭端点闭合或局部网格位移判通过。主姿势联系表用于确认变化，连续播放用于确认节奏，二者都应实际查看。若用户已反馈动作过弱，复验同一显示尺寸下的新版，不用“技术数据正常”代替改进效果。
- 节奏、幅度、重心和形变结合已确认的风格判断；刻意停顿、夸张挤压、滑行或悬浮按设计验收，不强制所有动作采用写实运动或相同的缓入缓出。
- 仅交付工程或预览时，目标游戏内的混合、事件和性能不自动列为必过项；需要运行时交付但未验证的项目标记待验证。性能按项目预算判断，不设置通用骨骼数、顶点数或帧率门槛。

例如站立呼吸待机：脚底漂移、肩部露缝或循环跳变应判不合格；呼吸可辨、身体稳定、外形完整、循环自然可判合格；在此基础上，胸腹、肩颈、头部与衣发有细微配合，并能体现放松、警觉或疲惫等性格状态，才进一步评价为优秀。

## 引用与画面检查

1. 运行 `spine_validate_references` 并回读目标对象，检查工程保存、动画名、时长和受影响轨道。
2. 显式提供 `atlasPath` 与 `imagePath`，用 `spine_render_preview(mode="sequence")` 查看整段姿势与层次，并检查返回的 `renderer`。当前实现实际要求图集和图片，不能仅依赖工具描述中的无图集回退。
3. 线框用于检查骨骼、枢轴与权重跟随，纯画面用于检查穿插、边缘、形变和层次。静态序列检查姿势，连续播放检查速度、滞后与接缝。先以实际显示大小和正常速度看整体，再慢放或逐帧检查关节、脸部、换图和遮挡变化；循环建议连续观看至少五轮，采样序列不能代替连续播放。
4. sequence 的 n 帧采样为 `duration*i/n`，不含精确终点。另检查 `0`、`duration-ε` 和结束状态；渲染器可能在 duration 时自动循环，原始端点与非循环播放也要检查。
5. 单帧预览优先显式传 `time`，避免预览默认 FPS 与工程帧率不同。没有导出宽高元数据时显式提供预览尺寸。
6. 按实际需求检查待机到动作、动作到待机，以及允许的中断和混合；确认结束姿势、表情、附件、约束和绘制顺序没有非预期残留。原地走跑结合场景移动速度判断滑步，不能只看固定位置预览。
7. 需要运行时交付时，在目标运行时核对画面、循环、动作混合和事件触发；按项目要求验证性能。编辑器或 MCP 预览通过不代替目标环境验证。

自行编写数值检查时，报告实际识别的附件类型、受检附件名称、顶点或三角形数量、有效采样数及最差时间点。预期存在网格或接点却未识别到对象、样本集合为空时，检查结果记为待验证并修正检测逻辑。检查有效性及当前 SDK 的类型识别方法见 [运行时诊断脚本](../references/mcp-workflows.md#运行时诊断脚本)。

发现缺画、关节露底、穿插或生硬时，按 [防穿帮与动作优化](motion-quality.md) 定位并修复；补绘后使用新贴图与新图集复验原问题帧及邻帧，覆盖关节极限、层次交换、换图和混合窗口。共用贴图、权重或 setup 变化时复查受影响的其他动作，并将修复前后证据与剩余缺画项写入验收结论。

完整预览参数见 [操作工作流](../references/mcp-workflows.md) 的“预览、导出与恢复”。预览不可用时明确视觉验证未完成。

## 渲染差异

- 有接缝或其他伪影时，对照源贴图、编辑器或目标运行时，区分预览器与工程问题。
- 参考女主的本次 MCP 预览可见脸部三角接缝，尚未完成原因定位，不应据此直接改脸部拓扑。
- 工具报告成功或 `renderer="spine-runtime"` 不能单独证明美术效果通过验收；查看实际产物并记录尚存问题。

## 验收结论

- 按适用的检查维度记录通过、不通过或待验证；不适用项说明原因。结论关联实际工程、动画名、当前快照或导出资源、预览路径，以及使用的播放速度、显示大小和运行时环境。
- 成品与制作前已通过的交互预览对照，核对动作方向、主要姿势、幅度和节奏；分别记录用户对方案的验收与成品检查结论，不能用方案通过代替成品通过。
- 问题记录为“动画名 + 时间或帧号 + 部位 + 现象 + 预期”，帧号注明 FPS。例如：`run，0.32 秒，右脚，支撑阶段在场景中向后滑动，预期相对地面稳定`。修复后对同一问题复验。
- 适用项全部通过才能判合格；任一必过项失败则不合格；必要证据缺失则待验证，明确尚未完成的检查，不能报告整体通过。优秀评价在合格基础上说明具体表现依据，不用主观总分覆盖缺陷。
- 引用、时间轴和端点数据检查只能提供技术证据；美术效果需要查看实际画面和连续播放，运行时行为需要在对应环境验证。预览不可用时保留已完成的技术检查，标记视觉验收待验证。

## 交付资源

- 按需求交付 `.spine`、预览或运行时数据，列出实际工程、动画名和输出路径。
- 可编辑工程及依赖图片按下方 [工程目录规范](#工程目录规范) 整理并回读验证。
- 需要运行时资源时，对实际交付的格式分别导出并执行下方 [导出文件新鲜度](#导出文件新鲜度) 检查；工程编辑不会自动更新旧 JSON、SKEL 或播放器快照。
- 核对目标运行时版本、纹理名、atlas 页面及所有页面图片。没有改贴图或 region 时可复用已核对图集；发生变化时再重新打包。
- `spine_pack_atlas` 的输出目录必须不存在或为空。首次交付可先打包到 `out/`，再将运行时数据导出到同一目录；已有 `out/` 非空时，先打包到工作项目 `.work/` 下的独立临时目录，校验后将 `.atlas` 与全部页面图片一起更新到 `out/`，并同步更新引用它们的预览路径。打包参数按目标运行时核对 PMA、旋转、裁边和多页需求，不把默认值作为项目约定。
- 默认交付可操作的成品播放器，不生成 GIF。真实运行时播放器或无损 PNG 帧播放器均须标明播放方式；帧资源可按需用 `spine_export_sheet` 准备。用户明确要求 GIF 时才使用 `spine_export_video(format="gif")`；按需 MP4/WebM 导出需要服务端 ffmpeg。

### 导出文件新鲜度

当前导出服务会扫描整个输出目录，`spine_export_animation` 的返回列表可能包含原有文件；例如请求 binary 后列表仍可能列出旧 JSON，不能据此认定 JSON 也已重导出。

- JSON 与 SKEL 都需交付时，分别显式请求相应格式。优先在本次任务独立的暂存目录导出，再验证并更新交付文件；复用目录时记录目标文件前后哈希 / 时间，并读取内容确认本次预期变更。未变哈希可以是确定性导出的正确结果，时间戳变化也不能独自证明内容正确。
- 对层序修复，检查新 JSON 的 setup / 动态层序；实际读取 SKEL 并在适用运行时核对同一关系。不同格式按骨骼、插槽和附件的稳定名称对齐，比较关键姿势及必要的世界空间采样，区分导出精度与真实差异；不能因文件存在就判同版。
- 确认播放器读取的是已验证的 JSON 或 SKEL，刷新后核对准确帧与实际画面，必要时更新资源版本参数。通过后一起更新截图、报告与校验索引，旧版证据留在工作目录，避免当前入口混用旧数据。

### 工程目录规范

交付根目录中的文件仅保留可编辑 `.spine` 工程与工作 `.psd`。其余产物按用途放入子目录，按任务实际交付内容创建。用户明确指定的布局优先。

| 子目录 | 内容 |
| --- | --- |
| `images/` | 工程依赖的全部部件 PNG |
| `previews/` | 播放器、预览帧、拆件联系表、重建图、蓝图和修复对照图 |
| `out/` | 运行时 JSON、SKEL、atlas 及其全部页面图片，直接存放在此目录 |
| `docs/` | 动作说明、素材计划、验收记录等 Markdown 文档 |
| `metadata/` | `spine_manifest.json`、初始摆位 JSON、绑定记录、验证报告和文件校验索引 |

`.spine` 工程与 `images/` 文件夹同级，工程图片路径设置为 `./images/`，附件纹理路径相对于该图片目录。交付或搬迁时保留工程与图片目录的相对关系，整个目录复制到其他位置后应能直接打开。

Spine 3.8.99 保存时会将 `images/` 规范化为 `./images/`。为避免 JSON 重建的严格回读比较误报，输入工程图片路径时直接使用 `./images/`，并核对保存后的实际值。

```text
exports/<task>/
  character.spine
  character_parts.psd
  images/
    stem.png
    leaf.png
  previews/
    index.html
  out/
    character.json
    character.skel
    character.atlas
    character.png
  docs/
    animation_brief.md
    asset_plan.md
    acceptance.md
  metadata/
    spine_manifest.json
    verification.json
    files.sha256.json
```

完整制作从拆件阶段规划最终工程目录，部件可直接导出到工程同级的 `images/` 文件夹。上例 `metadata/spine_manifest.json` 中的 `images_dir` 为 `../images`，`source_psd` 为 `../character_parts.psd`，采用补图的路径为 `../images/<part>.png`，预览证据路径为 `../previews/<file>`。运行记录和备份保留在工作项目 `.work/` 的任务目录。

整理已有交付目录时，按引用所在文件的新位置重算相对路径。清单中的部件 `file` 仍相对于 `images_dir`，其他补图和证据路径沿用其各自约定。`docs/` 文档引用清单时使用 `../metadata/`，引用预览时使用 `../previews/`。若校验索引位于 `metadata/files.sha256.json`，其 `file` 字段相对于该索引目录，整理后重新计算文件列表、大小与哈希。完成后检查根目录文件类型，并验证清单、文档链接、预览资源和校验索引均能定位到实际产物。

迁移图片后保存工程并重新导出回读，逐项确认附件对应的 PNG 在工程同级的 `images/` 中存在、名称与大小写匹配、图片内容完整。核对骨架、附件和动画数据，导入导出造成曲线表达变化时比较实际采样姿态与关键帧行为。单纯修改 JSON 中的图片路径或复制文件不能代替工程保存和回读验证。

运行时 `.json` / `.skel`、`.atlas` 与全部图集页面图片直接存放在 `out/` 中，预览放在 `previews/`。运行时图集与其所有页面图片保持配套，atlas 页面引用使用同目录图片文件名；导出 JSON 中保留的图片目录元数据按 JSON 所在位置换算为正确的相对路径，例如 `out/character.json` 对同级工程的部件目录使用 `../images/`。

## 失败与恢复

先检查具体错误、原文件是否保留、备份路径及是否发生外部保存冲突。JSON 重建只承诺可导出数据，编辑器文件夹、视图等专有信息由原始备份恢复。

`spine_rollback({projectPath})` 只列出备份；传 `backupId` 才执行恢复。备份数量有限，恢复前核对目标版本和后续有效修改，不把回滚作为盲目重试步骤。
