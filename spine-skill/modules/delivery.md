# 预览、交付与恢复

先读取 [工程通用](project.md)。使用当前保存后重新导出的快照，避免用旧 JSON 或旧 `.skel` 验证新动作。

## 动画验收标准

单图输入的动画先核对拆件产物和真实附件关系：按运动与遮挡分离的部件应有联系表、原位映射及对应附件。若仍以完整角色图的单个 region/mesh 制作动画，即使有多骨骼权重、FFD 或正常循环，也不满足交付要求。图集打包到一张 PNG 不影响判断，检查的是独立部件区域与附件，而非图集页数。

验收前明确动作含义、角色风格、时长、循环与否、衔接对象和交付范围。合格表示满足需求、没有影响使用的明显问题、交付可用；优秀还要求动作有重量、节奏、性格和表现力。骨骼数、关键帧数、模板生成成功或工具返回成功不作为质量通过依据。

同类角色可按 [已验收人工工程标准](../references/accepted-production-standard.md) 选择同用途、同状态的参考，在相同角色显示高度、固定取景和正常速度下比较。人工基线的通过状态来自用户确认；原始端点差异、自动模板匹配率或预览器伪影只作诊断线索，不据此否决已验收作品。新作仍需检查实际连续播放与适用的使用环境。

| 检查维度 | 合格要求 | 常见不合格表现 |
| --- | --- | --- |
| 动作含义 | 在实际显示大小和正常速度下能看懂动作，符合需求及角色性格 | 攻击像挥手、受击像鞠躬、待机幅度喧宾夺主 |
| 姿势与重心 | 关键姿势清楚，支撑、发力和重心变化可信；走跑结合角色在场景中的移动速度检查支撑脚 | 非预期滑步、脚底漂浮、失去支撑却没有相应调整 |
| 节奏与力度 | 按动作需要安排蓄力、发力、停顿和恢复，速度变化及受力反馈清楚 | 全程机械匀速、攻击无力、落地没有承重，或出现非预期抖动 |
| 身体与附属运动 | 主体带动关系合理，头发、衣摆等按材质和动作适量滞后、回弹，固定根部稳定 | 所有部件同步摆动、衣料无故飘动、跟随幅度抢过主动作 |
| 外形与层次 | 关节、轮廓、体积及前后遮挡符合设计，换图与 FFD 过渡合理 | 关节露缝、网格翻折、脸部拉坏、明显穿插或绘制顺序错误 |
| 循环与衔接 | 循环首尾姿势及速度趋势连续，IK、FFD、附件可见性和绘制顺序一致；单次动作结束和切换符合设计 | 每轮接缝顿挫、切换时跳姿势、残留表情或错误附件 |
| 工程与实际使用 | 保存回读、引用和交付资源完整；需要运行时交付时，在目标环境验证版本、贴图、混合、事件及约定的性能预算 | 未保存、丢图、导出旧动作、事件错位、运行时效果异常或超出预算 |

- 明显破图、动作含义错误、非预期循环跳变、资源缺失或目标运行时无法使用等问题必须修正，不能用其他表现项抵消。
- 按预期显示尺寸正常播放，检查主动作是否可读、是否达到用户要求的幅度；idle 不能只凭端点闭合或局部网格位移判通过。主姿势联系表用于确认变化，连续播放用于确认节奏，二者都应实际查看。若用户已反馈动作过弱，复验同一显示尺寸下的新版，不用“技术数据正常”代替改进效果。
- 节奏、幅度、重心和形变结合已确认的风格判断；刻意停顿、夸张挤压、滑行或悬浮按设计验收，不强制所有动作采用写实运动或相同的缓入缓出。
- 仅交付工程或预览时，目标游戏内的混合、事件和性能不自动列为必过项；需要运行时交付但未验证的项目标记待验证。性能按项目预算判断，不设置通用骨骼数、顶点数或帧率门槛。

例如站立呼吸待机：脚底漂移、肩部露缝或循环跳变应判不合格；呼吸可辨、身体稳定、外形完整、循环自然可判合格；在此基础上，胸腹、肩颈、头部与衣发有细微配合，并能体现放松、警觉或疲惫等性格状态，才进一步评价为优秀。

## 引用与画面检查

1. 运行 `spine_validate_references` 并回读目标对象，检查工程保存、动画名、时长和受影响轨道。
2. 显式提供 `atlasPath` 与 `imagePath`，用 `spine_render_preview(mode="sequence")` 查看整段姿势与层次，并检查返回的 `renderer`。当前实现实际要求图集和图片，不能仅依赖工具描述中的无图集回退。
3. 线框用于检查骨骼、枢轴与权重跟随，纯画面用于检查穿插、边缘、形变和层次。静态序列检查姿势，连续播放检查速度、滞后与接缝。先以实际显示大小和正常速度看整体，再慢放或逐帧检查关节、脸部、换图和遮挡变化；循环建议连续观看至少五轮，采样序列不能代替连续播放。
4. sequence 的 n 帧采样为 `duration*i/n`，不含精确终点。另检查 `0`、`duration-ε` 和结束状态；渲染器可能在 duration 时自动循环，原始端点与非循环播放也要检查。
5. 单帧预览优先显式传 `time`，避免预览默认 FPS 与工程帧率不同。没有导出宽高元数据时显式提供预览尺寸。
6. 按实际需求检查待机到动作、动作到待机，以及允许的中断和混合；确认结束姿势、表情、附件、约束和绘制顺序没有非预期残留。原地走跑结合场景移动速度判断滑步，不能只看固定位置预览。
7. 需要运行时交付时，在目标运行时核对画面、循环、动作混合和事件触发；按项目要求验证性能。编辑器或 MCP 预览通过不代替目标环境验证。

发现缺画、关节露底、穿插或生硬时，按 [防穿帮与动作优化](motion-quality.md) 定位并修复；补绘后使用新贴图与新图集复验原问题帧及邻帧，覆盖关节极限、层次交换、换图和混合窗口。共用贴图、权重或 setup 变化时复查受影响的其他动作，并将修复前后证据与剩余缺画项写入验收结论。

完整预览参数见 [操作工作流](../references/mcp-workflows.md) 的“预览、导出与恢复”。预览不可用时明确视觉验证未完成。

## 渲染差异

- 有接缝或其他伪影时，对照源贴图、编辑器或目标运行时，区分预览器与工程问题。
- 参考女主的本次 MCP 预览可见脸部三角接缝，尚未完成原因定位，不应据此直接改脸部拓扑。
- 工具报告成功或 `renderer="spine-runtime"` 不能单独证明美术效果通过验收；查看实际产物并记录尚存问题。

## 验收结论

- 按适用的检查维度记录通过、不通过或待验证；不适用项说明原因。结论关联实际工程、动画名、当前快照或导出资源、预览路径，以及使用的播放速度、显示大小和运行时环境。
- 问题记录为“动画名 + 时间或帧号 + 部位 + 现象 + 预期”，帧号注明 FPS。例如：`run，0.32 秒，右脚，支撑阶段在场景中向后滑动，预期相对地面稳定`。修复后对同一问题复验。
- 适用项全部通过才能判合格；任一必过项失败则不合格；必要证据缺失则待验证，明确尚未完成的检查，不能报告整体通过。优秀评价在合格基础上说明具体表现依据，不用主观总分覆盖缺陷。
- 引用、时间轴和端点数据检查只能提供技术证据；美术效果需要查看实际画面和连续播放，运行时行为需要在对应环境验证。预览不可用时保留已完成的技术检查，标记视觉验收待验证。

## 交付资源

- 按需求交付 `.spine`、预览或运行时数据，列出实际工程、动画名和输出路径。
- 需要运行时资源时，重新调用 `spine_export_animation(format="json"|"binary")`；动画编辑不会自动更新旧 `.skel`。
- 核对目标运行时版本、纹理名、atlas 页面及所有页面图片。没有改贴图或 region 时可复用已核对图集；发生变化时再重新打包。
- `spine_pack_atlas` 的输出目录必须不存在或为空。打包参数按目标运行时核对 PMA、旋转、裁边和多页需求，不把默认值作为项目约定。
- GIF 可用 `spine_export_video`，精灵表可用 `spine_export_sheet`；MP4/WebM 需要服务端 ffmpeg。

## 失败与恢复

先检查具体错误、原文件是否保留、备份路径及是否发生外部保存冲突。JSON 重建只承诺可导出数据，编辑器文件夹、视图等专有信息由原始备份恢复。

`spine_rollback({projectPath})` 只列出备份；传 `backupId` 才执行恢复。备份数量有限，恢复前核对目标版本和后续有效修改，不把回滚作为盲目重试步骤。
